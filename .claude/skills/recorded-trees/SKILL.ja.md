# 記録した木を確かめる

English version: [SKILL.md](./SKILL.md)

先に [conventions](../conventions/SKILL.ja.md) を読む。
レビューする人は、
[review](../review/SKILL.ja.md) の 2 節「入力」と 5 節「指摘と報告」にも従う。
コマンド、出力、表、
答えのファイルの形は
[recorded-trees.ja.md](../../../packages/tests/docs/recorded-trees.ja.md)
が定める。
この手順の前に、
その「走らせ方」「ブロックと項目」「確かめの表」「答え」「出すもの」の節を読む。

## 方針と基準

- 変更が足すか書き換える `ast.json` を、fixture を引く文と、
  木とトークンと位置の条件で確かめる。
  文書の条件を変えたときも、その場合の記録を読む（8 節）。
  `parse-error.json` はこの読み方の範囲に入らない。
  パーサーの記録の手順では、新しい拒否の記録を引き続き読む。
- 答えは、ブロックの言うことと木の値を比べた形で書く。
  「読んだ」「すべて合う」だけは答えにしない。
  答えの中身は 5 節が定める。
  コマンドは答えの有無だけを確かめる。
- レビューする人は、作者の答えを見る前に独立に答え、その後で比べる。
  自分の答えはレビューの報告に書き、作業ツリーには何も書かない。

## 1. コマンドを走らせる

記録した後、リポジトリの根で走らせる。

```sh
pnpm --filter @mmd-toolkit/tests run recorded-trees:check --base HEAD --places
```

この基点では、追跡していないファイルも含め、commit 前の作業の記録を確かめる。
レビューを頼む前には、`--base origin/main --places` で PR の全体を見る。
基点は、渡した ref と `HEAD` の merge base である。
コマンドには、その履歴を持つ git checkout が要り、archive では走らない。

出力を絞らずに最後まで読む。
最初の節に、変更の木か、すべての記録した木かと、その理由が出る。
決まりのファイルを手で並べず、出力が示す範囲を使う。

終了コード 2 は呼び方か git の誤りなので、呼び方や履歴を直して走らせ直す。
答えがないための終了コード 1 は、3〜5 節で行う作業の一覧である。
ほかの問題は先に解消する（2 節）。

## 2. 問題が出たとき

「Problems」を読む。
読めない記録、分類されていない節点の型、読めない答えや表のファイルも含む。
`checkTree()` の問題は、
そのメッセージを [検査](../../../packages/tests/docs/check-tree.ja.md#検査)
で探し、その条件を定める木とトークンと位置のブロックを読む。
答える前に、どこが誤っているかを決める。

- パーサー: 直し、
  [parser の 4.7 節](../parser/SKILL.ja.md#47-記録したパースの結果) の手順 4
  で記録し直す。
- 仕様: 定義の欠けか誤りを、
  [parser の 4.2 節](../parser/SKILL.ja.md#42-仕様を読み欠落を先に扱う) の手順 2
  のとおり伝える。
- 確かめの決まり、節点の分類、表: tests のパッケージに伝える。
  読めない答えは、9 節に従ってこの変更のファイルで直す。

`ast.json` を手で直さない。
[parser の 4.6 節](../parser/SKILL.ja.md#46-テスト) のとおり、
fixture のテストが記録する。

## 3. 変更の木ごとに、それを引く文で読む

出力の「Sentences that cite each changed tree」を使い、
[parser の 4.7 節](../parser/SKILL.ja.md#47-記録したパースの結果) の手順 3
に従う。
引く文の全体を読み、場合を定め、それが触れる木の部分を、その文と、
木とトークンと位置のブロックと比べる。
基点の答えがその木の中身の鍵を覆うとき以外は、
この変更の答えのファイルに木の答えを書く（5 節）。

引く文のない木は、そう書き、この段では比べない。
4 節の項目ごとの読みが、その図種を覆う。
引用の欠けとして仕様に伝えるのは、この変更が足した手書きの fixture だけ。
集めた入力（`source.kind` が `mermaid`）は、文が引かなくてよい。
文が引く集めた入力は、ほかの木と同じく読む。
出力が source kind を不明としたときは、
伝えるかを決める前に `expected.json` を読む。

## 4. 読む項目を読む

「Items to read」の項目をすべて読む。
場所が 0 の項目と、この変更の答えがあると示された項目も含む。
基点で答え済みの項目には、新しい答えは要らない。
項目ごとに次を行う。

1. 出力の書き出しだけでなく、文書のブロックを全部読み、
   `read with` に出る節もすべて読む。
2. 条件を理解するために、引用された場合の記録を読む。
   場合は読む手がかりであり、答えの単位ではない。
3. `--places` のすべての場所の値を、条件と比べる。
   木の全体が場所なら、
   `packages/parser` の `pnpm run show-trees <diagram> <fixture>` で読む。
   節点やトークンでも、表示された入力の抜粋に出ない欄や本文はそこで読む。
4. 場所が 0 のときは、入力と木を読み、その型の節点か、
   その種類のトークンになるはずの文字が入力にないと確かめる。
   誤った種類で記録されたために場所が 0 でも、読み落とさないためである。
5. 項目ごとに 1 つの答えを書き、読んだ木の中身の鍵を覆う。

文書が値を決めていなければ、未決定の木を記録として残さず、問いを伝える。
parser の 4.7 節の手順 1 のとおり。

## 5. 答えを書く

`packages/tests/recorded-trees/answers/` に、この変更のファイルを 1 つ置く。
形は [答え](../../../packages/tests/docs/recorded-trees.ja.md#答え) に従う。
変更の木の項目の鍵と中身の鍵は、「Missing answers」の雛形から写す。
文書で変わった項目は、「Items whose key changed」の鍵を使う（8 節）。
コマンドはファイルを書かない。
答えの本文は、fixture の `expected.json` の note と同じく英語で書く。
JSON の記録には、日本語の Markdown の対はない。

項目の答えには、次を書く。

- ブロックの言うことを、読み手の言葉で 1 文。
- 比べた値: 値の種類ごとに、場所の数と、ブロックの言うこととの比較。
- 場所が 0 のときは、その型の節点か種類のトークンになるはずの文字がないと、
  何を読んで確かめたか。
- 合うか、合わないか。
  合わない場所は、場所の鍵ですべて挙げ、記録を残す前に 2 節で原因を解消する。
- review スキルが定める、実行した（run）か読んだ（read）か。

木の答えには、引く文の文書と行、それぞれが示す場合、比べた木の部分、
比べたブロックの項目の鍵、合うかどうかを書く。
場合が木のどの部分にも触れないときは、そう書く。
引く文のない木には「no sentence cites it」と書き、
その図種の項目ごとの読みが覆うことと、新しく足した手書きの fixture なら、
引用の欠けを仕様に伝えたことを書く。
その木の中身の鍵は、項目の答えの木の鍵と同じく、雛形から取る。

合わないものは記録を残す前に解消し、ファイルには合う答えを残す。
コマンドを走らせ直し、問題も、項目と木の答えの欠けもなく、
終了コード 0 になるまで続ける。
これで 8 節の表の判断が済むわけではない。

## 6. 報告とマージの後

コマンドと基点、範囲とその理由、木の数、問題と直し方、
答えのファイルの道を報告する。
作者の報告に答えを写さない。
「Records this check does not read」に出る、変更した `parse-error.json` を並べ、
別に読んだ結果を parser の 4.7 節に従って示す。
読めなかった項目と木は、review の 5 節のとおり、何が読めず、その理由と、
読める人を示す。

何の証拠とするかは、conventions の「テストの実行」に従う。
`--base HEAD` の結果は、PR の全体の確かめにはならない。

[表を判断し終えるまで](../../../packages/tests/docs/recorded-trees.ja.md#表を判断し終えるまで)
のとおり、表のすべての項目を判断するまで、コマンドは CI に入らない。
その不在を報告し、手元の結果を使う。
CI で走るときは、その範囲と問題も読む。
決まりの変更と木の変更が main で合流した場合も含め、
マージの後の問題は 2 節で扱う。

## 7. 変更をレビューする

1. 依存を入れ、無関係な作業の変更がない git checkout で、PR の先頭を使う。
   `--base origin/main --places` で走らせる。
   コマンドは作業ツリーに書かない。
   commit 前の変更と追跡していないファイルも数えるので、
   無関係な変更のある作業ツリーや archive では、PR の範囲にならない。
   CI で走っていれば、ログの基点を踏まえて木の数を比べ、違いの理由を調べる。
   走っていなければ、その不在を報告する。
2. 問題を読む。
   条件を破る木は review の 5 節での重い指摘で、答えの欠けは読みの漏れである。
   ランナーか、それがたどるファイルの変更で、すべての木に当たることを、
   出力の説明で確かめる。
3. 作者の答えを見る前に、同じ項目と木について 3 節と 4 節を行い、
   文書で変わった項目には 8 節も行う。
   自分の答えをレビューの報告に書く。
   それまで、答えのファイル、その差分（PR の diff を含む）、
   作者の報告や説明の答えを読まない。
   書き終えてから比べる。
   木、文書、答えのどれが誤っているかの根拠とともに違いを指摘し、
   比べた形のない答えも指摘する。
   答えのファイルの差分は、道と種類を見て、この変更のファイルを足す以外に、
   ほかの変更のファイルを消したり、書き換えたりしていれば指摘する。
   この確かめに答えの本文を読む必要はない。
4. この変更が足すか変えた表の行と、名指したテストのファイルを変えた行を読む。
   `shown` は、名指したテストを読み、ほかの条件ではなく、
   このブロックの条件のすべての場合を合わせて破っていることを確かめる。
   読むだけで足りなければ、その場合を持つ名指した記録の木と入力を、
   自分の scratchpad に写して、その場合のとおりに壊し、
   小さなスクリプトから `node` でリポジトリの
   `packages/tests/src/check-tree/index.ts` を呼ぶ。
   たとえば、種類の条件には、
   `ErIdentifier` のトークンを `Identifier` から `RawText` に変える。
   ビルドは要らない。
   木は場合で選び、数や無作為では選ばない。
   報告しない場合があれば `shown` の行は誤りで、tests のパッケージへの重い指摘。
5. `no-condition` は、ブロック全体を読み、
   kind と note を
   [確かめの表](../../../packages/tests/docs/recorded-trees.ja.md#確かめの表)
   と照らす。
   `not-in-diagram` で名指した文書も読む。
   条件の例は場合であり、条件と紹介が混じるブロックにも条件がある。
   どちらも `no-condition` に隠すのは、その項目をだれも読まなくするため、
   重い指摘。
6. 「Stale rows of the coverage table」と「Items not judged by the coverage
   table」を読む。
   出力の基点との比較を使い、この変更で増えた行や項目を指摘する。
   前からある欠けは、この変更の指摘にしない。
   コマンドは落ちなくても、増えた分は、同じ PR で tests のパッケージが判断する。
   文書だけの変更と `checkTree()` のテストの変更にも、この確かめを行う。

review の 5 節に従い、自分の答えと run/read の根拠を報告する。

## 8. 木とトークンと位置の文書が変わったとき

ブロックの本文か、リンク先の節が変わると、項目の鍵が変わることがある。
引用だけの変更では変わらない。
`--base origin/main --places` で走らせ、
理由と読む fixture を出す「Items whose key changed」を使う。

- ブロックの本文が変わった: そのブロックが引く fixture。
- リンク先の節が変わった: その 2 つの版のどちらか一方にだけあるブロックが、
  その版で引く fixture のうち、項目の図種のもの。
  変わった文の場合を示すものであり、本文の変わらない項目のブロック自身の引用で、
  置き換えない。
- 両方が変わった: 上の和。

項目ごとに、その受理の fixture の `ast.json` を、
新しい本文とリンク先の節で読む項目のブロックと、4 節のとおりに比べる。
拒否の記録はここでは読まない。
出力が示す、存在しない fixture と木のない fixture を控え、
読まなかった記録を報告する。
項目の鍵と中身の鍵は、「Items whose key changed」から取る。
文書だけの変更ではコマンドは答えを求めないが、5 節に従い、
その中身の鍵を覆う項目の答えを 1 つ、この変更のファイルに書く。
前の答えは 9 節のとおり残す。

古い行とまだ判断していない項目は、同じ PR で tests のパッケージに、
[tests-tree-checks](../tests-tree-checks/SKILL.ja.md) の手順 8 での判断を頼む。
文書の作業として判断しない。
新しいか書き換えたブロックに引用した fixture がなければ、
conventions に従って場合ごとの fixture が要るので、仕様のレビューが求める。
リンク先の節で変わったブロックにも当たるが、消えたブロックと、
本文の変わらないブロックには求めない。

レビューする人は、作者の答えを見る前に同じ比較を行い、その後で比べる。
答えのファイルの変更と、
古い行やまだ判断していない項目が基点より増えていないかも、7 節のとおり確かめる。

## 9. 答えのファイルを保つ

書くのは、この変更のファイルだけ。
マージの後も残し、後の変更で書き換えない。
ほかの変更の答えのファイルは、足すことも、消すことも、書き換えることもしない。
記録が変わったら、新しい中身に、この変更のファイルで答える。
項目や中身の鍵が合わなくなった答えも、項目が `shown` になった答えも残す。
中身が同じ改名や移動は、recorded-trees.ja.md の「答え」が定めるとおり、
既存の答えが覆う。
