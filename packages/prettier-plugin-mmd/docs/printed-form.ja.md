# 印字する形の決め方

整形は、mermaid.js が描くものを変えない（AGENTS.md の 4）。
描くものが同じになる書き方は、1 つの形で印字する。
描くものが変わる書き方は、書かれたまま残す。
この文書は、どの形で印字するかと、その理由を定める。

図種ごとの規則は、その図種の文書（`flowchart.md`、`gantt.md` など）にある。
それぞれの規則の理由は、下の決まりのどれかである。

## 形を決めるもの

印字する形でいちばん大事なのは、読みやすいことである。
描くものが、対象にする版の mermaid.js のどれでも同じになる書き方が、
何通りかあるとき、整形ツールは、その中でいちばん読みやすい形で印字する。

下の決まりは、どの形がいちばん読みやすいかを定めたものである。
決まりとして書き、書かれた順に当てるのは、その場その場で判断すると、
判断が人によって違うからである。
同じ種類の記号が、ある図種ではこの形、別の図種では別の形、と印字されてしまう。
決まりは、文章を読みやすくするためにある。
そのため、決まりを当てた形が、描くものが同じになる別の形より読みにくいときは、
決まりの方が誤っている。
そのときは、形を決め直して、決まりを直す。
決め直すのは、作業をしている人ひとりではない。
決め方は、AGENTS.md の 4 にある。

1. 記号の横の空白は、Prettier が同じ種類の記号の横に印字する空白にする。
   記号ではない場所（行の終わり、テキストの終わり、空行）の空白は、
   その場所がある言語のどれでも Prettier が同じに印字するときは、
   Prettier がそこに印字する空白にする。
   整形ツールは Prettier のプラグインで、図は、
   Prettier が整形するコードと同じファイルに並ぶ。
   同じ種類の記号や場所が、図の中でも、まわりのコードの中でも、
   同じに読めるようにするためである。
2. Prettier にない種類の隙間は、ほかの図種が印字する形にする。
   同じ種類の隙間を、どの図種でも 1 つの形にするためである。
   1 つの図種で覚えた形を、次の図種でもそのまま読める。
3. 綴りは、mermaid.js の文書の例が使う形にする。
   図を書く人が知っている形で、つかえずに読めるからである。

読みやすさは、mermaid.js の文書の書き方に合わせることより先である。
空白があった方が読みやすい所では、mermaid.js の文書が空白なしで書いていても、
空白を入れる。
mermaid.js の文書は C4 図の引数を `$link="x"` と書くが、
整形ツールは `$link = "x"` と印字する。
綴りを mermaid.js の文書の形にするのも、同じ理由である。
知っている綴りがいちばん読みやすいからで、文書が書いているからではない。
文書の綴りが別の綴りより読みにくいときは、綴りの決まりの方を直す。

## 1. 記号の横の空白

記号の横の空白は、
Prettier が整形する言語で同じ種類の記号の横に印字する空白にする。
記号ではない場所の空白も同じで、
その場所がある言語のどれでも Prettier が同じに印字するものは、
Prettier の印字する空白にする。
行の終わり、テキストの終わり、空行がそうである。
表は、種類ごとに、Prettier が印字する形と、
整形ツールが同じように印字する文を示す。
Prettier の例は、言語を書いていないものは JavaScript である。

最初の 2 種類の波括弧は、Prettier のオブジェクトと配列に当たり、3 つ目は、
その一方に何も入れないものに当たる。

ブロックの中の行は、ブロックを開く行の後にある文とコメント行で、
閉じる行があれば、そこまでである（`subgraph S` と `end`、`loop` と `end`、
`{` とその `}`）。
Prettier は、それらを開く行より 1 段深く印字する。
JavaScript（`if (a) {`。`function f() {}` の本体では、
`"use strict";` のような指令と、コメント行と、`return 1;` が同じ段に立つ）、
CSS（規則）、HTML（要素）がそうで、
閉じる行のない YAML の入れ子のマッピングの行もそうである。
閉じる行は開く行と同じ段に置き、
1 つの本体を閉じて次の本体を開く行（`} else {`）も同じ段に置く。
コメント行（`// c`、`/* c */`、`# c`、`<!-- c -->`）は、
まわりの行と同じ段に置く。
図種のヘッダーと、`section` の行と、cynefin の領域の行は、
YAML のマッピングのキーと同じく、閉じる行のないこのブロックを開く。
その後の行は、それを開く行と同じ段の次の行まで、1 段深く置く。
ブロックの中のどの行も、何を持つかによらず、その段に置く。
文でも、コメント行でも、
この図種のディレクティブの行（単独の行の `%%{x}%%`）でもよい。
ディレクティブは、mermaid.js がコメントと同じく、テキストを読む前に取り除く。
同じ理由で、行の途中で 2 つの単位の間にあるディレクティブと、
行の最後の単位の後にあるディレクティブは、
JavaScript と CSS でトークンの間や最後のトークンの後に立てるコメント、
つまりブロックコメント（`/* c */`）と同じ種類の印である。
2 つの単位の間では、その横の空白は、
表の「2 つのものの間にあるコメント」の行の空白で、
Prettier が同じ所のブロックコメントの横に印字する空白である。
`x = a/*c*/+b;` は `x = a /*c*/ + b;` に、
`x = [/*c*/1];` は `x = [/*c*/ 1];` に、
`x = {  /*c*/  };` は `x = {/*c*/};` に印字される。
行の最後の単位の後では、表の「行の中で、何かの後にあるコメント」の行の空白で、
ディレクティブの前に空白 1 つを置き、行の終わりでは後ろに空白を置かない。
`x = a;/*c*/` は `x = a; /*c*/` に、`x = a;   /*c*/   ` は `x = a; /*c*/` に、
`x = a /*c*/ /*d*/` は `x = a; /*c*/ /*d*/` に印字される。
その最後の単位が、行を 1 段深く置くブロックを開く印のときは、
ディレクティブはブロックの中の自分の行に置く。
`{` と、複数行に書いた railroad 図の `sequence`、`choice`、`optional`、
`oneOrMore`、`zeroOrMore` の `(` が、その印である。
Prettier は、行の終わりの `{` の後のブロックコメントを、ブロックの中に移す。
`x = { /*c*/`、改行、`a: 1,`、改行、`};` は、`x = {`、
1 段内側のそれぞれの行の `/*c*/` と `a: 1,`、`};` に印字され、
`if (a) { /*c*/` と CSS の `a {   /*c*/` も同じである。
次の所では、mermaid.js がそれを決める。
ディレクティブの両側の空白を、決まった幅の 1 つの隙間として読む所、
行の終わりのディレクティブの前のテキストを、行の終わりまでの値として読む所、
行の終わりの隠れた形の後に空白がないテキストを拒否する所である。
詳しくは [mermaid.js が空白を許さない所](#mermaidjs-が空白を許さない所)を参照。
JavaScript のテンプレートリテラルの中のテキストは、書かれたまま残り、
複数行にわたる値のテキストも同じである。
説明ブロックの `{` と `}` の間の行は、本文の行も、
その間のコメント行とディレクティブの行も、そのテキストであって、
この行のブロックの中の行ではない。
この行が与えるのは、そのブロックの閉じる `}` だけで、間の行は与えない。

eventmodeling 図の文は、ヘッダーより 1 段深くではなく、桁 1 に置く。
対象の版の mermaid.js はどれも、
`data` と `note` のブロックを閉じる `}` を字下げすると受け付けないので、
その `}` は桁 1 に立つ。
文を 1 段深くすると、`}` はそのブロックを開く行より左に立つことになる。
文を桁 1 に置けば、どの `}` も、この行の閉じる行と同じく、
そのブロックを開く行と同じ桁に立つ。
この形は、AGENTS.md の 4 が、
同じに描かれるほかの形より読みにくい形を与える規則として、
直すものと述べるこの行の形を直したものである。
eventmodeling 図の側の決まりは、
[Indentation](./eventmodeling.ja.md#indentation)にある。

キーワードは、2 つのものの間に立つ（`a in b`）か、
取るものの前に立つ（`return x`、`typeof y`、`throw e`、
CSS の `@media screen` と `@import "a.css"`）。
どちらの行に当たるかは、コロンの種類と同じく、働きで決める。
キーワードが取るものは、括弧で始まってもよい。
`return  [800, 600]` は `return [800, 600];` と印字するので、
Wardley マップの `size [800, 600]` と XY チャートの `x-axis [jan, feb]` で、
値の並びを開く `[` の前にも、空白 1 つを置く。
CSS の宣言の値のように、並んで続く値の間には空白を 1 つ置くので、
文が取る値を開く `[` は、前にある名前やタイトルの後でも、空白 1 つを置く。
`anchor Coord   [0.3, 0.6]` は `anchor Coord [0.3, 0.6]` と印字する。
radar 図の曲線の値を開く `{`（`curve c{1, 2}`）も同じ括弧で、
Prettier が `return  {a: 1}` を `return { a: 1 };` と印字するのと同じく、
前に空白 1 つを置く。
名前のタイトルやラベルを開く括弧は、添字の `[` が添字を付けるものに接し、
前に空白を置かないのと同じく、名前に接する。
flowchart の `subgraph S [t]` は `subgraph S[t]` と、
architecture 図の `service a (server) [A]` は `service a(server)[A]`
と印字する。
呼び出しを開く `(` と、ブロックを開く `{` は、それぞれの行のままにする。

数の範囲の始まりと終わりをつなぐ `-`（packet 図の `0-15`）は、
2 つのものの間に置く記号ではない。
2 つの数で 1 つの範囲を表すので、両側に空白を置かない。
2 つのものの間に置く、ほかの記号の行のとおり両側に空白を置くと、
`0 - 15` は引き算に読めるが、`0-15` は 1 つの範囲に読める。

コメントは行の最後のものの後に立ち、Prettier は、書かれた空白によらず、
その間に空白 1 つを印字する（`x = 1;// c` は `x = 1; // c` と印字される）。
空白を足すと mermaid.js のテキストの読み方が変わるときは、
コメントは接したままにし、その事実をその図種の文書が述べる。
XY チャートでは、mermaid.js は、
1 文字の単位に接する `%%` をその文字と一緒に読むので、
`title A B%% c` の title は `A` で、`title A B %% c` の title は `AB` になる。

コメントの本文は、印の後から、先頭の空白と中の空白の連なりも含めて、
書かれたまま印字する。
Prettier は、JavaScript の `//no space` と `//    spaced   text`、
YAML の `#    spaced   text` を書かれたまま印字し、落とすのは、
どの行でもそうするように、行の終わりの空白だけである。

行の終わり、テキストの終わり、空行は、JavaScript、CSS、YAML、Markdown で同じで、
空白だけの行は、4 つとも空行にする。
Markdown で、改行の前の 2 つ以上の空白は、改行（hard line break）の記号で、
行の終わりの空白ではない。
Prettier は、その空白を 2 つにして印字し、
それ以外の行の終わりの空白は落とす（`a ` と改行を `a` と改行にする）。
行頭は、ブロックの中の行を除いて、この規則の場所ではない。
ブロックの中の行は、その名の行が与える。
それ以外で文が置かれる位置は、[規則 2](#2-prettier-にない種類の隙間)が決める。
U+2028 か U+2029 の後のコメント行が前の行に結ぶ行は、その行も規則 2 も置かず、
図種の文書の字下げの文も当たらない。
そこで印字するものは、すべての図種について、
[U+2028 か U+2029 の後のコメント行](./compatibility.ja.md#u2028-か-u2029-の後のコメント行)
が示す。
オプションや Prettier 自身が決めるもので、記号や場所の種類で決まらないものは、
ここでは規則にしない。
字下げ 1 段の単位（`useTabs` と `tabWidth`）、改行コード（`endOfLine`）、
BOM がそうである。
整形ツールは、それらを Prettier のとおりにし、図種の文書は、
それを事実として書く。

Prettier は、HTML の属性の `=` を、空白なしで印字する（`<a href="x">`）。
C4 図の引数は、呼び出しの引数の並びの中にある。
Prettier は、そこに書く既定値の `=` を、両側に空白を置いて印字する。

### コロンがどの種類かの決め方

Prettier は、コロンを 3 通りに印字する。
そのため、コロンは、空白を決める前に、どの種類かを決める。

- キーのコロンは、キーに付け、後に空白を 1 つ置く。
  JavaScript の `{ a: 1 }`、YAML の `key: value`、CSS の `color: red` である。
- 条件式のコロンは、2 つの結果の間に置き、両側に空白を 1 つずつ置く。
  `c ? d : e` である。
- 名前の中のコロンは、両側とも詰める。
  CSS のセレクター `a:hover` である。

空白は、コロンの後の文が何のものかを示す。
コロンが前の名前に付いていると、後の文は、その名前の値に見える。
`s1 --> s2: go` と書くと、`go` が `s2` の値に見える。
しかし mermaid.js は、`go` を、`s1` から `s2` への遷移のラベルとして読む。
両側に空白を置くと、コロンは、遷移とそのラベルの間に立つ。

種類は、次の手順を、この順に当てて決める。

1. 名前の中のコロン。
   コロンの前と後を合わせて、1 つのものを指す名前になるコロンである。
   `a:R -- L:b` では、辺の端は、サービス `a` の `R` の側である。
   両側とも、空白を置かない。
2. キーのコロン。
   その行が、1 つの名前に値を 1 つ与えるコロンである。
   requirement の `id: 1`、radar 図の curve の `m: 60`、
   スタイルの `fill: #f00` がそうである。
   行がそうであるかがはっきりしないときは、
   同じ名前の行をもう 1 つ書いて確かめる。
   キーのコロンなら、項目は増えない。
   pie 図で、同じラベルの行を 2 つ書いても、mermaid.js が読む項目は 1 つである。
   キーのコロンの前には空白を置かず、後に空白を 1 つ置く。
3. それ以外のコロン。
   同じ名前の行を書くたびに何かが足されるコロン（クラスにメンバー、
   図にタスク）か、コロンの後の文が、
   前の名前だけのものではないコロン（遷移のラベル）である。
   このコロンは、2 つのものの間に置く記号と読める。
   こうしたコロンには、キーのコロンと同じ形で書かれるものもある。
   前に空白を置く形と、前を詰める形のどちらにするかは、
   Prettier の種類からは決まらないので、
   固定した mermaid.js の文書の例を数えて決める。
   数えるのは、その行を、コロンの後に空白を置いて書いた例だけである。
   そのうち、コロンの前に空白を置いた例と、前を詰めた例の数を比べる。
   多い方が少ない方の 2 倍以上あれば、多い方の形で印字する。
   2 倍に届かないとき、または、数える例が 1 つもないときは、
   2 つのものの間に置く記号として、両側に空白を 1 つずつ置く。
   どちらの形でも、コロンの後には空白を 1 つ置く。

同じ記号は、行によって種類を変えない。
同じコロンが、1 つの図種の何種類かの行に出てくるときは、
読み方がいちばん少ない行に手順を当て、その結果をどの行にも使う。
Venn 図の大きさは、`set A : 20` では 1 つの集合の後に、
`union A, B : 3` では 2 つの集合の後に続く。
後者では、大きさは `B` の値ではない。
そのため、大きさのコロンは、どちらの行でも、キーのコロンではない。

コロンの両側を詰めて、`set A:3` の形で書いた例は、手順 3 では数えない。
mermaid.js の文書は、Venn 図の大きさをこの形で書く。
コロンの後に空白のない形は印字しないので、この例は、
比べる 2 つの形のどちらも示さない。

コロンの種類がこの手順からはっきりしないときは、種類を仮に決めて印字しない。
形は [4](#4-どの決まりも形を決めない所) のとおりに決め、その行を下の表に足す。

下の表の理由の欄で「例」と書くのは、固定した mermaid.js の文書の例である。

| 行                            | 手順 | 印字する形                       | 理由                                                                                                            |
| ----------------------------- | ---- | -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| architecture 図の辺の端       | 1    | `a:R -- L:b`                     | 側は、辺の端の一部である。                                                                                      |
| pie 図の項目の値              | 2    | `"Dogs": 386`                    | 同じラベルの行をもう 1 つ書いても、項目は増えない。                                                             |
| 図のタイトルと説明            | 2    | `accTitle: text`                 | その行は、図に、タイトルか説明を 1 つ与える。                                                                   |
| 状態の説明                    | 3    | `s2: a description`              | もう 1 行書くと、説明が 1 行足される。例は、コロンの前を詰めた書き方が、空けた書き方の 2 倍以上ある。           |
| 状態の間の遷移のラベル        | 3    | `s1 --> s2 : go`                 | ラベルは `s2` のものではなく、遷移のものである。例は、コロンの前を空けた書き方が、詰めた書き方の 2 倍以上ある。 |
| ER 図の関係のラベル           | 3    | `A \|\|--o{ B : has`             | 遷移と同じ。                                                                                                    |
| クラスの間の関係のラベル      | 3    | `A --> B : label`                | 遷移と同じ。                                                                                                    |
| 行がクラスに足すメンバー      | 3    | `Animal : +int age`              | 1 行ごとに、メンバーが 1 つ足される。例は、コロンの前を空けた書き方が、詰めた書き方の 2 倍以上ある。            |
| sequence 図のメッセージの文   | 3    | `A ->> B: text`                  | 文は、メッセージのものである。例は、コロンの前を詰めて書く。                                                    |
| Gantt 図のタスクのデータ      | 3    | `Task one : a1, 2024-01-01, 30d` | 1 行が 1 つのタスクで、同じ名前のタスクが 2 つあってもよい。例は、コロンの前を空けて書く。                      |
| timeline の期間の出来事       | 3    | `2004 : Facebook : Google`       | コロンは、期間とその出来事を区切る。例は、コロンの前を空けて書く。                                              |
| Venn 図の集合や重なりの大きさ | 3    | `set A["Alpha"] : 20`            | 1 行ごとに、集合か重なりが 1 つ足される。コロンの後に空白を置いた例は、1 つもない。                             |

例の数え方と、手順 3 で決まるすべての行の数は、
[コロンの前の空白を決める例](./compatibility.ja.md#コロンの前の空白を決める例)
にある。

### 桁をそろえるための余白

何行かの同じ記号を 1 つの桁にそろえるための余白は、記号の横の空白ではない。
この決まりでは決めない。

Prettier は、`const a   = 1` を `const a = 1;` と印字する。
次の行が `const bbb = 2` でも同じである。
これを、桁をそろえないという決まりとは読まない。
JavaScript、CSS、YAML の行は表の行ではないので、Prettier には、
そこで保つ桁がない。
テキストが表であるときは、Prettier も桁をそろえる。
Markdown の表では、セルに空白を足して、列の幅をそろえる。

そのため、行の桁をそろえるかどうかは、行の種類ごとに、その図種の文書で決める。

- Gantt 図のセクションのタスクは、名前とそのデータの行である。
  プリンターは、名前がコロンの前に余白を入れて書かれたセクションで、
  コロンを 1 つの桁にそろえる。
  これは、[規則 4](#4-どの決まりも形を決めない所)で決めた形で、
  [規則 4 で決めた形](#規則-4-で決めた形)にある。
  いつそろえるかと、書かれたまま残すセクションは、
  [タスクのデータ](./gantt.ja.md#タスクのデータ) が定める。
- timeline と user journey で、コロンの桁をそろえている余白は、
  書かれたまま残す。
  [period と event](./timeline.ja.md#period-と-event) と
  [タスクのデータ](./journey.ja.md#タスクのデータ) が定める。
  timeline では、[規則 4](#4-どの決まりも形を決めない所)で決めた形で、
  [規則 4 で決めた形](#規則-4-で決めた形)にある。

これと別の桁のそろえ方は、[4](#4-どの決まりも形を決めない所) のとおりに決める。

### mermaid.js が空白を許さない所

記号の横の空白を入れるのは、
対象にする版（[対象にする mermaid.js の版](#対象にする-mermaidjs-の版)を見よ）の
mermaid.js のどれもが、空白があっても同じに読む所である。
入れないのは、mermaid.js が拒否するか、別の読み方をする所だけである。
flowchart の `class` 文の id の並び（`class A,B c`）、
block 図の幅のコロンの後（`a:2`）、
flowchart の形の性質のコロンの横（`A[|borders:lt|text]`）が、その例である。
空白を入れない並びは、
[コンマで区切る一覧](./compatibility.ja.md#コンマで区切る一覧) にある。

mermaid.js がコロンの後の空白を拒否する所では、前にも空白を置かない。
Prettier は、前にだけ空白を置いたコロンを印字しないからである。
block 図の幅は、`a :2` と書かれていても、`a:2` と印字する。

mermaid.js が、ディレクティブの両側の空白を、
決まった幅の 1 つの隙間として読む所では、片側にだけ空白を置く。
class 図の `note for` の単位はちょうど 1 文字の空白を読み、
mermaid.js は `note %%{init: {}}%% for A "t"` を拒否する。
そのため、
`note%%{init: {}}%% for A "t"` は `note %%{init: {}}%%for A "t"`
と印字する（[ディレクティブ](./flowchart.ja.md#ディレクティブ)を見よ）。

mermaid.js が、行の終わりのディレクティブの前のテキストを、
行の終わりまでの値として読む所では、
ディレクティブを行の最後の単位に接したまま置く。
前に空白を置くと、その空白で値が終わるからである。
そこで mermaid.js が空白を拒否する所も同じである。
フレームが読む eventmodeling の `data` ブロックの本文を開く `{`
の後も同じである。
その値は `{` の後に続くものを持つので、ディレクティブをブロックの中に移しても、
前に空白を置いても、値が変わる。
timeline の `title T%%{wrap}%%` は、ディレクティブを `T` に接したまま残す。
mermaid.js は `title T %%{wrap}%%` から題 `T ` を読むからである。
そのような所は、
[行の終わりのディレクティブ](./compatibility.ja.md#行の終わりのディレクティブ)
にある。

隠れた形（`%%{!x}%%`）が文を終え、次の行に別の文が続く所では、
その後の空白がないテキストを mermaid.js が拒否する図種で、その空白を残す。
architecture 図の `service a %%{!h}%%` の後、
次の行の `service b` の前がその例である。
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
に、その図種ごとの行がある。

flowchart、swimlane 図、agentflow 図で、
ラベルの先頭の空白がないと mermaid.js が別に読むか、
拒否するラベル（引用符で囲まれた文字列ではなく、`/`、`\`、`-`、`"` で始まるか、
最初の語が `@` を含むラベル。
[ラベルの内側の空白](./flowchart.ja.md#ラベルの内側の空白)を参照）では、
どの形でも、また `|` の間のテキストでも、ラベルの両端の内側に空白 1 つを置く。
`A[ /x/]` は `A[ /x/ ]` と印字する。
規則 1 は括弧の内側に空白を置かないので、
mermaid.js が要る空白を先頭にだけ残すことになり、書き損じに見える。
末尾にも置けば、その空白が意図したものだと分かる。
この形は、AGENTS.md の 4 が、
同じに描かれるほかの形より読みにくい形を与える規則として、
直すものと述べる規則 1 の形を直したものである。
斜めの形の閉じの `?]` と `=]` の前には空白を置かない。
mermaid.js が、その空白と `?` や `=` をテキストとして読むからである。

### 木が丸ごと持つテキスト

この決まりが決めるのは、
パーサーの構文木がトークンとして持つ記号の横の空白である。
木が丸ごと持つテキストとは、ラベルと文字列のテキスト、
mermaid.js が YAML として読むデータブロック（`@{ … }`）の本体である。
その中は、書かれたまま印字する。
flowchart の `A@{ shape : circle }` は、コロンの前の空白を保つ。
整形ツールがそのテキストの中で何を変えるかは、その図種の文書が定める。

## 2. Prettier にない種類の隙間

Prettier にない種類の隙間は、ほかの図種が同じ種類の隙間を印字する形にする。

規則 1 が与えるブロックの中の行を除いて、文が置かれる位置もこの種の隙間で、
各図種の文書は、字下げの文でそれを示す。
詳しくは [行頭](#1-記号の横の空白) を参照。

## 3. 綴り

綴り（キーワードの大文字小文字、文字列の引用符、数の桁、ヘッダーの向き）は、
固定した mermaid.js の文書の例を数えて決める。
ある形が、ほかのどの形と比べても 2 倍以上多く使われていれば、その形で印字する。
ER 図の `"CUSTOMER" ||--o{ "ORDER" : places` は、
`CUSTOMER ||--o{ ORDER : places` と印字する。
そこまで多く使われている形がないとき、または、
文書の例にその書き方が 1 つも出てこないときは、規則 3 は形を与えず、
[規則 4](#4-どの決まりも形を決めない所)で形が決まるまで、書かれたまま残す。

ヘッダーの名前の `-beta` は、例外である。
`-beta` つきの名前と、なしの名前の両方を、
その図種を持つ対象の版のすべてが両方を読み、同じに描くときは、
`-beta` なしの名前で印字する。
`treemap-beta` は `treemap` と、`ishikawa-beta` は `ishikawa` と印字する。
短い名前のほうが読みやすく、あとまで残る名前でもある。
mermaid.js は、block、sankey、xychart、packet の 4 つの図種から、
安定したときに `-beta` を外した。
文書の例も、それからは、この 4 つを `-beta` なしで書いている。
（[ヘッダーの名前](./compatibility.ja.md#ヘッダーの名前)を参照）。
`block-beta` は書かれたまま残す。
対象の版の一部が、その名前しか読まないからである。

罫線文字で書かれた treeView 図の木も例外である。
mermaid.js の文書の木の図 13 件のうち、10 件は字下げで書かれているので、
規則 3 は字下げの形を与える。
罫線文字で書かれた木は、mermaid.js が読む木から描き直して、罫線文字で印字する。
ただし、本文を書かれたまま残す場合は除く。
詳しくは [Branch prefixes](./treeview.ja.md#branch-prefixes) を参照。
文字そのものが各行の構造を示し、`├` は次の兄弟があること、
`└` は最後の子であること、`│` は上の段の兄弟が続くことを表す。
字下げでは、ノードが最後の子であることや上の段の兄弟が続くことは、
その下の行の列だけで示される。
これらの文字を木の構造に応じた所に新しく描き、
図が mermaid.js
の読むものを表すようにする（[Modes](./treeview.ja.md#modes)を参照）。
書かれた文字を保って列だけを移すと、最後の子の `├` や、
兄弟が続かない所の `│` が残ってしまう。
この形は、AGENTS.md の 4 が、
同じに描かれるほかの形より読みにくい形を与える規則として、
直すものと述べる規則 3 の形を直したものである。
この形は、字下げで書かれた木には及ばず、規則 3 のとおり字下げで印字する。
そのような木のすべてに罫線の形があるわけではない。
罫線の図では、引用名の 2 行目や別行の注釈のように、
枝の前置部分がないまま続く字下げされた行を mermaid.js が拒否するからである。

文字列は、そのテキストが、それが立つ呼び出しを閉じる記号か、
スタイルの記号を持つときは、引用符がなくても mermaid.js が同じに読むときも、
引用符を保つ。
C4 図の `)` を持つ別名（`Person("a)", "A")`）と、
`:` と `;` を持つ kanban のカードのラベル（`A["aStyle:#x;yb"]`）である。
引用符がないと、`Person(a), "A")` は `a` の後で終わる呼び出しに見え、
`A[aStyle:#x;yb]` はスタイルを持つカードに見える。
この形は、AGENTS.md の 4 が、
同じに描かれるほかの形より読みにくい形を与える規則として、
直すものと述べる規則 3 の形を直したものである。
それぞれの図種の側の決まりは、
[Quotes](./c4.ja.md#quotes)と[Quotes](./kanban.ja.md#quotes)にある。

## 4. どの決まりも形を決めない所

上の 1 から 3 のどれからも形が出ないときは、どの形がいちばん読みやすいかが、
まだ決まっていない。
そのときは、作業をしている人の判断だけで、公開済みの版の出力を変えない。
形は、AGENTS.md の 4 にある決め方で決め、ここの決まりに書き足してから印字する。

### 規則 4 で決めた形

次の形は、規則 1 から 3 のどれも形を与えない所で、
AGENTS.md の 4 にある決め方で決めた形である。
図種を挙げない項目は、flowchart と swimlane 図について決めた形である。
どこに当て、どこに当てないかは、図種の文書が書く。

- 文はそれぞれ自分の行に置く。
  `;` で区切って 1 行に書いた文は、行に分ける。
- 文の終わりの `;` は取り除き、トップレベルでそれだけで置かれた `;` も取り除く。
- Prettier の `printWidth` オプションにかかわらず、行を折り返さない。
- flowchart では、辺のラベルは、書かれた形のまま残す。
  2 つの矢印の間のテキストか、矢印の後の `|` の間のテキストである。
- `useTabs` では、
  複数行のデータブロック（`@{ … }`）を持つ文は書かれたまま印字する。
- flowchart、agentflow、kanban では、
  `printWidth` より広い行にある 1 行のデータブロック（`@{ … }`）を、
  複数行の形のほうが読みやすいとき、1 行に 1 項目ずつ複数行で印字する。
- timeline では、period のコロンの桁をそろえる余白を書かれたまま残す。
  `Long : y` の上の `A    : x` は、空白をそのまま持つ。
- Gantt 図では、
  セクションの名前のどれかがコロンの前に余白を入れて書かれているとき、
  そのセクションのタスクのコロンを、
  最長の名前の後に空白 1 つを置いた桁にそろえる。

## 対象にする mermaid.js の版

確かめは固定した mermaid.js だけで行うが、
整形した文章はほかの版の mermaid.js でも描かれる。
対象にする版は、固定した版が公開される前の 18 か月の間に公開された版のうち、
メジャーバージョンごとの、いちばん小さいマイナーバージョンと、
いちばん大きいマイナーバージョンである。
どれも、そのマイナーバージョンの最新のパッチを使う。
その間に足された図種は、
そのメジャーバージョンのいちばん小さいマイナーバージョンでは読めない。
そこで、その図種についてだけ、いちばん小さいマイナーバージョンの代わりに、
その図種を持つ最初のマイナーバージョンを対象にする。
1 つの図種の文章を確かめる版は、メジャーバージョンごとに多くて 2 つである。
版の一覧と、それぞれの版がどの図種について対象になるかは、
[対象にする mermaid.js の版](./compatibility.ja.md#対象にする-mermaidjs-の版)
にある。

そのため、形は、次のどちらかのときも、書かれたまま残す。
1 つは、書かれた形を受け付ける対象の版の中に、
印字する形を受け付けない版があるときである。
もう 1 つは、対象の版の中に、印字する形を、
書かれた形とは違う図に描く版があるときである。
次の 3 つは、その例である。

- ヘッダーの名前（`block-beta` と `block`）は、対象の版の間で受け付けが違う。
- `@` を含む flowchart のラベルの `[` の後の空白（`A[ user@example.com ]`）は、
  それがないと、対象の版の一部がラベルを拒否する。
- subgraph のある flowchart のヘッダーの向き（`TB` と `TD`）は、
  対象の版の一部が違う描き方をする。

これに当たる場合は、どれも、
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
の表に 1 行ずつあり、その行が、どの版のために残すのかを、版の名前で書いている。
固定している版もその形を要るときは、その版も挙げる。
固定している版そのものが拒否するか、違う図に描く形は、ほかの版が替わっても残す。
形を残す相手の版の名前を書くのは、この表だけである。
それぞれの図種の文書は、理由を書いて、表の行を指す。
確かめの記録は、いくつの版で、どの版で描いたかを書いてよい。
版が対象でなくなっても、そこは何も変わらないからである。
固定する版を上げて、行が挙げた版が 1 つも対象でなくなったら、その規則を外し、
上の決まりが与える形で印字する。

書かれた形を読んでも描くときにエラーで止まり、印字することになる形は描く版は、
その形については対象にしない。
整形した文章はその版でも開かれ、
整形によってそこで描くものから何も失われないので、
書かれた形を残す理由にはならない。
sequence 図のブロックのラベルにある空白の連なりは、そのような形である。
詳しくは
[同じに描かれるテキスト中の空白の連なり](./compatibility.ja.md#同じに描かれるテキスト中の空白の連なり)
を参照。

どの版が形を足したか、変えたかは、mermaid.js の CHANGELOG.md か、
文法の履歴で分かる。

## 確かめ方と、Db を変える整形

整形が描くものを変えないことは、整形が Db を変えないことで確かめる。
Db は、mermaid.js が文章から読み取った内容である。
Db を変えても描くものを変えない整形は、例外とする。
例外の種類には、それぞれ、次の 3 つがある。
1 つめは、その種類を定義する節である。
2 つめは、描くものが変わらない理由を示す、
固定した mermaid.js のコードへのリンクである。
3 つめは、整形の前と後の文章をそれぞれ描いた結果である。
テストは、その種類の違いを元に戻してから、Db を比べる。
元に戻す関数は種類ごとに 1 つあり、
`packages/prettier-plugin-mmd/tests/db-comparison.ts` が呼ぶ。
固定した mermaid.js を更新するときは、例外ごとに、描いて確かめ直す。
種類は、次のとおりである。

- eventmodeling のブロックの本体の、限られた ASCII の空白の余白の変更。
  [データブロック](./eventmodeling.ja.md#data-blocks) が定める。
- 対象になる state の note の段落の、余白の変更。
  [ノート](./state.ja.md#ノート) が定める。
- スタイルの最初の `:` と `,` のまわりの空白、
  スタイルの語の間の空白とタブの連なり（空白 1 つになる）、
  スタイルの末尾の空白。
  [同じに描かれるスタイル](./compatibility.ja.md#同じに描かれるスタイル)
  が定める。
- タイトル、Gantt 図の日付の書式と軸の書式、C4 図の説明の、
  先頭と末尾の空白とタブ。
  timeline の期間と出来事、state 図の別名の 2 つ目の説明、
  Gantt 図のタスクの名前、user journey のタスクの説明の、末尾の空白とタブ。
  user journey のタスクの説明の末尾の空白とタブは、
  最初のコロンの前の空白とタブである。
  Langium の型と quadrant 図のタイトルの末尾と、
  先頭（quadrant 図の U+2028 と U+2029 を除く）の、
  仕様が空白と定める文字（改行しない空白と U+3000 を含む）。
  [同じに描かれるキーワードの後のテキスト](./compatibility.ja.md#同じに描かれるキーワードの後のテキスト)
  が定める。
- mermaid.js が取り除いて描く文章の中の、空白とタブの連なり。
  タイトル、アクセシビリティの説明、
  ラベルを SVG の文字として描く図種のラベルである。
  [同じに描かれるテキスト中の空白の連なり](./compatibility.ja.md#同じに描かれるテキスト中の空白の連なり)
  が定める。
- flowchart、agentflow、class、Gantt の各図の `click` の呼び出しの、
  引数のまわりの空白。
  [同じに描かれる呼び出しの引数](./compatibility.ja.md#同じに描かれる呼び出しの引数)
  が定める。
- mindmap のノードと kanban のカードの文章の、両端の空白とタブ。
  [同じに描かれる mindmap のテキスト](./compatibility.ja.md#同じに描かれる-mindmap-のテキスト)
  が定める。
- flowchart、swimlane、agentflow の各図のラベルの `labelType`。
  引用符で囲んだラベルと、囲まないラベルで違う。
  [同じに描かれるラベル](./compatibility.ja.md#同じに描かれるラベル) が定める。
- スタイルの中の色の 16 進数の大文字小文字（整形は小文字で印字する）と、
  sequence 図の `rect` と `box`、Venn 図の `style` の、
  色の関数の各コンマの後の空白。
  [同じに描かれる色](./compatibility.ja.md#同じに描かれる色) が定める。
