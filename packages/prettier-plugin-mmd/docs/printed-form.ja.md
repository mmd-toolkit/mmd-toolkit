# 印字する形の決め方

整形は、mermaid.js が描くものを変えない（AGENTS.md の 4）。
描くものが同じになる書き方は、1 つの形で印字する。
描くものが変わる書き方は、書かれたまま残す。
この文書は、どの形で印字するかを定める。
決まりは、書かれた順に当てる。
どちらが読みやすいかの判断に残る場合を、作らないためである。

図種ごとの規則は、その図種の文書（`flowchart.md`、`gantt.md` など）にある。
規則の理由は、下の決まりのどれかである。

## 1. 記号の横の空白

記号の横の空白は、
Prettier が整形する言語で同じ種類の記号の横に印字する空白にする。

| 記号                       | 空白                    | 書かれた形                          | 印字する形                    |
| -------------------------- | ----------------------- | ----------------------------------- | ----------------------------- |
| コンマ                     | 前は詰め、後に空白 1 つ | ER 図の `class A,B c`               | `class A, B c`                |
| `=`                        | 両側に空白 1 つずつ     | C4 図の `Person(a, "A", $link="x")` | `Person(a, "A", $link = "x")` |
| 鍵のコロン                 | 前は詰め、後に空白 1 つ | pie 図の `"Dogs" : 386`             | `"Dogs": 386`                 |
| 2 つのものの間に置く記号   | 両側に空白 1 つずつ     | flowchart の `A-->B`                | `A --> B`                     |
| 丸括弧と角括弧             | 内側は詰める            | flowchart の `A( text )`            | `A(text)`                     |
| 名前と値の組を並べた波括弧 | 内側に空白 1 つ         | radar 図の `curve c{m: 60, s: 70}`  | `curve c{ m: 60, s: 70 }`     |
| 値だけを並べた波括弧       | 内側は詰める            | radar 図の `curve d{ 85, 90 }`      | `curve d{85, 90}`             |

2 種類の波括弧は、Prettier のオブジェクトと配列に当たる。

### コロンがどの種類かの決め方

コロンの後には、どちらの種類でも、空白を 1 つ置く。
コロンの前の空白は、次の手順を、この順に当てて決める。

1. 鍵のコロン。
   その行は、1 つの名前に、値を 1 つ与える。
   同じ名前の行をもう 1 つ書いても、項目は増えない。
   pie 図で、同じラベルの行を 2 つ書いても、mermaid.js が読む項目が 1 つなのが、
   その例である。
   前には空白を置かない。
2. それ以外のコロンは、2 つのものの間に置く記号とも読める。
   固定した mermaid.js の文書の例のうち、
   その行をコロンの後に空白を置いて書いた例が、前の空白を決める。
   例が、もう一方の形より 2 倍以上多く書く形にする。
3. その例から形が決まらないときは、コロンを、2 つのものの間に置く記号として、
   両側に空白を 1 つずつ置く。
   決まらないのは、コロンの後に空白を置いた例が 1 つもないときと、どちらの形も、
   もう一方の 2 倍に届かないときである。

コロンの両側を詰めて書いた例は、印字するどの形とも違う書き方なので、
手順 2 では数えない。
文書が Venn 図の大きさを `set A:3` と書くのが、その例である。

| 行                            | 手順 | 印字する形                       | 理由                                                                                       |
| ----------------------------- | ---- | -------------------------------- | ------------------------------------------------------------------------------------------ |
| pie 図の項目の値              | 1    | `"Dogs": 386`                    | 同じラベルの行をもう 1 つ書いても、項目は増えない。                                        |
| 状態の説明                    | 2    | `s2: a description`              | もう 1 行書くと、説明が 1 行足される。例は、コロンの前を詰めて書く。                       |
| 状態の間の遷移のラベル        | 2    | `A --> B : go`                   | ラベルは `B` のものではなく、遷移のものである。例は、コロンの前を空けて書く。              |
| ER 図の関係のラベル           | 2    | `A \|\|--o{ B : has`             | 遷移と同じ。                                                                               |
| クラスの間の関係のラベル      | 2    | `A --> B : label`                | 遷移と同じ。                                                                               |
| 行がクラスに足すメンバー      | 2    | `Animal : +int age`              | 1 行ごとに、メンバーが 1 つ足される。例は、コロンの前を空けて書く。                        |
| sequence 図のメッセージの文   | 2    | `A ->> B: text`                  | 1 行が 1 つのメッセージである。例は、コロンの前を詰めて書く。                              |
| Gantt 図のタスクのデータ      | 2    | `Task one : a1, 2024-01-01, 30d` | 1 行が 1 つのタスクで、同じ名前のタスクが 2 つあってもよい。例は、コロンの前を空けて書く。 |
| timeline の期間の出来事       | 2    | `2004 : Facebook : Google`       | コロンは、期間とその出来事を区切る。例は、コロンの前を空けて書く。                         |
| Venn 図の集合や重なりの大きさ | 3    | `set A["Alpha"] : 20`            | 1 行ごとに、集合か重なりが 1 つ足される。コロンの後に空白を置いた例は、1 つもない。        |

例の数は、それぞれの図種の文書にある。

### 桁をそろえるための余白

Gantt 図のタスクのコロンのように、何行かにわたって桁をそろえるための余白は、
記号の横の空白に入らない。
Prettier はそれらの言語でその種類の余白を扱わないので、この決まりでは決めない。

### mermaid.js が空白を許さない所

この空白を入れるのは、
対象にする版（[対象にする mermaid.js の版](#対象にする-mermaidjs-の版)を見よ）の
mermaid.js のどれもが、空白があっても同じに読む所である。
入れないのは、mermaid.js が拒否するか、別の読み方をする所だけである。
flowchart の `class` 文の id の並び（`class A,B c`）が、その例である。

## 2. Prettier にない種類の隙間

Prettier にない種類の隙間は、ほかの図種が同じ種類の隙間を印字する形にする。

## 3. 綴り

綴り（キーワードの大文字小文字、文字列の引用符、数の桁、ヘッダーの向き）は、
固定した mermaid.js の文書の例が、ほかのどの形よりも 2 倍以上多く使う形にする。
ER 図の `"CUSTOMER" ||--o{ "ORDER" : places` は、
`CUSTOMER ||--o{ ORDER : places` と印字する。
そのように多く使われる形がないとき、または例がその綴りを使わないときは、
書かれたまま残す。

## 4. どの決まりも形を決めない所

どの決まりも形を決めないときは、どちらが読みやすいかの判断だけで、
公開済みの版の出力を変えない。
よりよいと考える形は、書かれた文と両方の出力を付けて、ユーザーに提案する。
決まった内容は、ここの決まりに書き足す。

## 対象にする mermaid.js の版

確かめは固定した mermaid.js だけで行うが、
整形した文章はほかの版の mermaid.js でも描かれる。
対象にする版は、固定した版が公開される前の 18 か月の間に公開された版のうち、
メジャーバージョンごとの、いちばん小さいマイナーバージョンと、
いちばん大きいマイナーバージョンである。
その間に足された図種については、
その図種を持つ最初のマイナーバージョンも対象にする。
どれも、そのマイナーバージョンの最新のパッチを使う。
版の一覧は、
[対象にする mermaid.js の版](./compatibility.ja.md#対象にする-mermaidjs-の版)
にある。

そこで、印字する形が、
書かれた形を受け付ける対象の版すべてで受け付けられるとは限らないとき、または、
そのうちの版が違う描き方をするときも、書かれたまま残す。

- ヘッダーの名前（`block-beta` と `block`）は、版によって受け付けが違う。
- `@` を含む flowchart のラベルの `[` の後の空白（`A[ user@example.com ]`）は、
  それがないと 11.7.0 から 12.0.0 までの版がラベルを拒否する。
- flowchart のヘッダーの向き（`TB` と `TD`）は、
  11.10.0 より前の版が違う描き方をする。

どの版が形を足したか、変えたかは、mermaid.js の CHANGELOG.md か、
文法の履歴で分かる。

## 確かめ方と、Db を変える整形

確かめる方法は、整形が Db を変えないことである。
Db を変えても描くものを変えない整形は、例外とする。
例外は種類ごとに、定義する節と、描画が変わらない理由を示す、
固定した mermaid.js のコードへのリンクと、両方の文章を描いた結果を持つ。
テストは、その種類の違いを戻した Db を比べる。
関数は種類ごとに 1 つで、
`packages/prettier-plugin-mmd/tests/db-comparison.ts` が呼ぶ。
固定した mermaid.js を更新するときは、例外ごとに、描いて確かめ直す。
種類は、次のとおりである。

- eventmodeling のブロックの本体の、限られた ASCII の空白の余白の変更。
  [Data blocks](./eventmodeling.ja.md#data-blocks) が定める。
- 対象になる state の note の段落の、余白の変更。
  [ノート](./state.ja.md#ノート) が定める。
- スタイルの最初の `:` と `,` のまわりの空白、
  スタイルの語の間の空白とタブの連なり（空白 1 つになる）、
  スタイルの末尾の空白。
  [同じに描かれるスタイル](./compatibility.ja.md#同じに描かれるスタイル)
  が定める。
- タイトル、Gantt 図の日付の書式と軸の書式、C4 図の説明の、先頭と末尾の空白。
  timeline の期間と出来事、state 図の別名の 2 つ目の説明、
  Gantt 図のタスクの名前の、末尾の空白。
  [同じに描かれるキーワードの後のテキスト](./compatibility.ja.md#同じに描かれるキーワードの後のテキスト)
  が定める。
- mermaid.js が取り除いて描く文章の中の、空白とタブの連なり。
  タイトル、アクセシビリティの説明、
  ラベルを SVG の文字として描く図種のラベルである。
  [同じに描かれるテキスト中の空白の連なり](./compatibility.ja.md#同じに描かれるテキスト中の空白の連なり)
  が定める。
- flowchart、agentflow、class、Gantt の各図の `click` の呼び出しの、
  引数のまわりの空白。
  [同じに描かれる呼び出しの引数](./compatibility.ja.md#同じに描かれる呼び出しの引数)
  が定める。
- mindmap のノードと kanban のカードの文章の、両端の空白とタブ。
  [同じに描かれる mindmap のテキスト](./compatibility.ja.md#同じに描かれる-mindmap-のテキスト)
  が定める。
- flowchart、swimlane、agentflow の各図のラベルの `labelType`。
  引用符で囲んだラベルと、囲まないラベルで違う。
  [同じに描かれるラベル](./compatibility.ja.md#同じに描かれるラベル) が定める。
- スタイルの中の色の 16 進数の大文字小文字（整形は小文字で印字する）と、
  sequence 図の `rect` と `box`、Venn 図の `style` の、
  色の関数の各コンマの後の空白。
  [同じに描かれる色](./compatibility.ja.md#同じに描かれる色) が定める。
