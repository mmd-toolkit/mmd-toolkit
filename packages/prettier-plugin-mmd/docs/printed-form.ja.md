# 印字する形の決め方

整形は、mermaid.js が描くものを変えない（AGENTS.md の 4）。
描くものが同じになる書き方は、1 つの形で印字する。
描くものが変わる書き方は、書かれたまま残す。
この文書は、どの形で印字するかと、その理由を定める。

図種ごとの規則は、その図種の文書（`flowchart.md`、`gantt.md` など）にある。
それぞれの規則の理由は、下の決まりのどれかである。

## 形を決めるもの

印字する形でいちばん大事なのは、読みやすいことである。
描くものが、対象にする版の mermaid.js のどれでも同じになる書き方が、
何通りかあるとき、整形ツールは、その中でいちばん読みやすい形で印字する。

下の決まりは、どの形がいちばん読みやすいかを定めたものである。
決まりとして書き、書かれた順に当てるのは、その場その場で判断すると、
判断が人によって違うからである。
同じ種類の記号が、ある図種ではこの形、別の図種では別の形、と印字されてしまう。
決まりは、文章を読みやすくするためにある。
そのため、決まりを当てた形が、描くものが同じになる別の形より読みにくいときは、
決まりの方が誤っている。
そのときは、形を決め直して、決まりを直す。
決め直すのは、作業をしている人ひとりではない。
決め方は、AGENTS.md の 4 にある。

1. 記号の横の空白は、Prettier が同じ種類の記号の横に印字する空白にする。
   整形ツールは Prettier のプラグインで、図は、
   Prettier が整形するコードと同じファイルに並ぶ。
   同じ種類の記号が、図の中でも、まわりのコードの中でも、
   同じに読めるようにするためである。
2. Prettier にない種類の隙間は、ほかの図種が印字する形にする。
   同じ種類の隙間を、どの図種でも 1 つの形にするためである。
   1 つの図種で覚えた形を、次の図種でもそのまま読める。
3. 綴りは、mermaid.js の文書の例が使う形にする。
   図を書く人が知っている形で、つかえずに読めるからである。

読みやすさは、mermaid.js の文書の書き方に合わせることより先である。
空白があった方が読みやすい所では、mermaid.js の文書が空白なしで書いていても、
空白を入れる。
mermaid.js の文書は C4 図の引数を `$link="x"` と書くが、
整形ツールは `$link = "x"` と印字する。
綴りを mermaid.js の文書の形にするのも、同じ理由である。
知っている綴りがいちばん読みやすいからで、文書が書いているからではない。
文書の綴りが別の綴りより読みにくいときは、綴りの決まりの方を直す。

## 1. 記号の横の空白

記号の横の空白は、
Prettier が整形する言語で同じ種類の記号の横に印字する空白にする。
表は、種類ごとに、Prettier が印字する形と、
整形ツールが同じように印字する文を示す。
Prettier の例は、言語を書いていないものは JavaScript である。

| 記号                             | Prettier                                                  | 空白                    | 書かれた形                          | 印字する形                    |
| -------------------------------- | --------------------------------------------------------- | ----------------------- | ----------------------------------- | ----------------------------- |
| コンマ                           | `f(a,b)` を `f(a, b);` と印字する                         | 前は詰め、後に空白 1 つ | ER 図の `class A,B c`               | `class A, B c`                |
| 名前に値を与える `=`             | `function f(a=1) {}` を `function f(a = 1) {}` と印字する | 両側に空白 1 つずつ     | C4 図の `Person(a, "A", $link="x")` | `Person(a, "A", $link = "x")` |
| キーのコロン                     | `x = {a : 1}` を `x = { a: 1 };` と印字する               | 前は詰め、後に空白 1 つ | pie 図の `"Dogs" : 386`             | `"Dogs": 386`                 |
| 2 つのものの間に置くコロン       | `y = c ? d:e` を `y = c ? d : e;` と印字する              | 両側に空白 1 つずつ     | state 図の `s1 --> s2: go`          | `s1 --> s2 : go`              |
| 名前の中のコロン                 | CSS のセレクター `a:hover` は `a:hover` のまま            | 両側とも詰める          | architecture 図の `a : R -- L : b`  | `a:R -- L:b`                  |
| 2 つのものの間に置く、ほかの記号 | `x = a+b` を `x = a + b;` と印字する                      | 両側に空白 1 つずつ     | flowchart の `A-->B`                | `A --> B`                     |
| 丸括弧と角括弧                   | `f( a )` を `f(a);` と印字する                            | 内側は詰める            | flowchart の `A( text )`            | `A(text)`                     |
| 名前と値の組を並べた波括弧       | `x = {a:1}` を `x = { a: 1 };` と印字する                 | 内側に空白 1 つ         | radar 図の `curve c{m: 60, s: 70}`  | `curve c{ m: 60, s: 70 }`     |
| 値だけを並べた波括弧             | `x = [ 1, 2 ]` を `x = [1, 2];` と印字する                | 内側は詰める            | radar 図の `curve d{ 85, 90 }`      | `curve d{85, 90}`             |

2 種類の波括弧は、Prettier のオブジェクトと配列に当たる。

Prettier は、HTML の属性の `=` を、空白なしで印字する（`<a href="x">`）。
C4 図の引数は、呼び出しの引数の並びの中にある。
Prettier は、そこに書く既定値の `=` を、両側に空白を置いて印字する。

### コロンがどの種類かの決め方

Prettier は、コロンを 3 通りに印字する。
そのため、コロンは、空白を決める前に、どの種類かを決める。

- キーのコロンは、キーに付け、後に空白を 1 つ置く。
  JavaScript の `{ a: 1 }`、YAML の `key: value`、CSS の `color: red` である。
- 条件式のコロンは、2 つの結果の間に置き、両側に空白を 1 つずつ置く。
  `c ? d : e` である。
- 名前の中のコロンは、両側とも詰める。
  CSS のセレクター `a:hover` である。

空白は、コロンの後の文が何のものかを示す。
コロンが前の名前に付いていると、後の文は、その名前の値に見える。
`s1 --> s2: go` と書くと、`go` が `s2` の値に見える。
しかし mermaid.js は、`go` を、`s1` から `s2` への遷移のラベルとして読む。
両側に空白を置くと、コロンは、遷移とそのラベルの間に立つ。

種類は、次の手順を、この順に当てて決める。

1. 名前の中のコロン。
   コロンの前と後を合わせて、1 つのものを指す名前になるコロンである。
   `a:R -- L:b` では、辺の端は、サービス `a` の `R` の側である。
   両側とも、空白を置かない。
2. キーのコロン。
   その行が、1 つの名前に値を 1 つ与えるコロンである。
   requirement の `id: 1`、radar 図の curve の `m: 60`、
   スタイルの `fill: #f00` がそうである。
   行がそうであるかがはっきりしないときは、
   同じ名前の行をもう 1 つ書いて確かめる。
   キーのコロンなら、項目は増えない。
   pie 図で、同じラベルの行を 2 つ書いても、mermaid.js が読む項目は 1 つである。
   キーのコロンの前には空白を置かず、後に空白を 1 つ置く。
3. それ以外のコロン。
   同じ名前の行を書くたびに何かが足されるコロン（クラスにメンバー、
   図にタスク）か、コロンの後の文が、
   前の名前だけのものではないコロン（遷移のラベル）である。
   このコロンは、2 つのものの間に置く記号と読める。
   こうしたコロンには、キーのコロンと同じ形で書かれるものもある。
   前に空白を置く形と、前を詰める形のどちらにするかは、
   Prettier の種類からは決まらないので、
   固定した mermaid.js の文書の例を数えて決める。
   数えるのは、その行を、コロンの後に空白を置いて書いた例だけである。
   そのうち、コロンの前に空白を置いた例と、前を詰めた例の数を比べる。
   多い方が少ない方の 2 倍以上あれば、多い方の形で印字する。
   2 倍に届かないとき、または、数える例が 1 つもないときは、
   2 つのものの間に置く記号として、両側に空白を 1 つずつ置く。
   どちらの形でも、コロンの後には空白を 1 つ置く。

同じ記号は、行によって種類を変えない。
同じコロンが、1 つの図種の何種類かの行に出てくるときは、
読み方がいちばん少ない行に手順を当て、その結果をどの行にも使う。
Venn 図の大きさは、`set A : 20` では 1 つの集合の後に、
`union A, B : 3` では 2 つの集合の後に続く。
後者では、大きさは `B` の値ではない。
そのため、大きさのコロンは、どちらの行でも、キーのコロンではない。

コロンの両側を詰めて、`set A:3` の形で書いた例は、手順 3 では数えない。
mermaid.js の文書は、Venn 図の大きさをこの形で書く。
コロンの後に空白のない形は印字しないので、この例は、
比べる 2 つの形のどちらも示さない。

コロンの種類がこの手順からはっきりしないときは、種類を仮に決めて印字しない。
形は [4](#4-どの決まりも形を決めない所) のとおりに決め、その行を下の表に足す。

下の表の理由の欄で「例」と書くのは、固定した mermaid.js の文書の例である。

| 行                            | 手順 | 印字する形                       | 理由                                                                                                            |
| ----------------------------- | ---- | -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| architecture 図の辺の端       | 1    | `a:R -- L:b`                     | 側は、辺の端の一部である。                                                                                      |
| pie 図の項目の値              | 2    | `"Dogs": 386`                    | 同じラベルの行をもう 1 つ書いても、項目は増えない。                                                             |
| 図のタイトルと説明            | 2    | `accTitle: text`                 | その行は、図に、タイトルか説明を 1 つ与える。                                                                   |
| 状態の説明                    | 3    | `s2: a description`              | もう 1 行書くと、説明が 1 行足される。例は、コロンの前を詰めた書き方が、空けた書き方の 2 倍以上ある。           |
| 状態の間の遷移のラベル        | 3    | `s1 --> s2 : go`                 | ラベルは `s2` のものではなく、遷移のものである。例は、コロンの前を空けた書き方が、詰めた書き方の 2 倍以上ある。 |
| ER 図の関係のラベル           | 3    | `A \|\|--o{ B : has`             | 遷移と同じ。                                                                                                    |
| クラスの間の関係のラベル      | 3    | `A --> B : label`                | 遷移と同じ。                                                                                                    |
| 行がクラスに足すメンバー      | 3    | `Animal : +int age`              | 1 行ごとに、メンバーが 1 つ足される。例は、コロンの前を空けた書き方が、詰めた書き方の 2 倍以上ある。            |
| sequence 図のメッセージの文   | 3    | `A ->> B: text`                  | 文は、メッセージのものである。例は、コロンの前を詰めて書く。                                                    |
| Gantt 図のタスクのデータ      | 3    | `Task one : a1, 2024-01-01, 30d` | 1 行が 1 つのタスクで、同じ名前のタスクが 2 つあってもよい。例は、コロンの前を空けて書く。                      |
| timeline の期間の出来事       | 3    | `2004 : Facebook : Google`       | コロンは、期間とその出来事を区切る。例は、コロンの前を空けて書く。                                              |
| Venn 図の集合や重なりの大きさ | 3    | `set A["Alpha"] : 20`            | 1 行ごとに、集合か重なりが 1 つ足される。コロンの後に空白を置いた例は、1 つもない。                             |

例の数え方と、手順 3 で決まるすべての行の数は、
[コロンの前の空白を決める例](./compatibility.ja.md#コロンの前の空白を決める例)
にある。

### 桁をそろえるための余白

何行かの同じ記号を 1 つの桁にそろえるための余白は、記号の横の空白ではない。
この決まりでは決めない。

Prettier は、`const a   = 1` を `const a = 1;` と印字する。
次の行が `const bbb = 2` でも同じである。
これを、桁をそろえないという決まりとは読まない。
JavaScript、CSS、YAML の行は表の行ではないので、Prettier には、
そこで保つ桁がない。
テキストが表であるときは、Prettier も桁をそろえる。
Markdown の表では、セルに空白を足して、列の幅をそろえる。

そのため、行の桁をそろえるかどうかは、行の種類ごとに、その図種の文書で決める。

- Gantt 図のセクションのタスクは、名前とそのデータの行である。
  プリンターは、名前がコロンの前に余白を入れて書かれたセクションで、
  コロンを 1 つの桁にそろえる。
  いつそろえるかと、書かれたまま残すセクションは、
  [タスクのデータ](./gantt.ja.md#タスクのデータ) が定める。
- timeline と user journey で、コロンの桁をそろえている余白は、
  書かれたまま残す。
  [period と event](./timeline.ja.md#period-と-event) と
  [タスクのデータ](./journey.ja.md#タスクのデータ) が定める。

これと別の桁のそろえ方は、[4](#4-どの決まりも形を決めない所) のとおりに決める。

### mermaid.js が空白を許さない所

記号の横の空白を入れるのは、
対象にする版（[対象にする mermaid.js の版](#対象にする-mermaidjs-の版)を見よ）の
mermaid.js のどれもが、空白があっても同じに読む所である。
入れないのは、mermaid.js が拒否するか、別の読み方をする所だけである。
flowchart の `class` 文の id の並び（`class A,B c`）、
block 図の幅のコロンの後（`a:2`）、
flowchart の形の性質のコロンの横（`A[|borders:lt|text]`）が、その例である。
空白を入れない並びは、
[コンマで区切る一覧](./compatibility.ja.md#コンマで区切る一覧) にある。

mermaid.js がコロンの後の空白を拒否する所では、前にも空白を置かない。
Prettier は、前にだけ空白を置いたコロンを印字しないからである。
block 図の幅は、`a :2` と書かれていても、`a:2` と印字する。

### 木が丸ごと持つテキスト

この決まりが決めるのは、
パーサーの構文木がトークンとして持つ記号の横の空白である。
木が丸ごと持つテキストとは、ラベルと文字列のテキスト、
mermaid.js が YAML として読むデータブロック（`@{ … }`）の本体である。
その中は、書かれたまま印字する。
flowchart の `A@{ shape : circle }` は、コロンの前の空白を保つ。
整形ツールがそのテキストの中で何を変えるかは、その図種の文書が定める。

## 2. Prettier にない種類の隙間

Prettier にない種類の隙間は、ほかの図種が同じ種類の隙間を印字する形にする。
キーワードとそのテキストの間の隙間が、その例である。
pie 図の `title    Pets` は `title Pets` と印字し、
Gantt 図の `title    Plan` も `title Plan` と印字する。

## 3. 綴り

綴り（キーワードの大文字小文字、文字列の引用符、数の桁、ヘッダーの向き）は、
固定した mermaid.js の文書の例を数えて決める。
ある形が、ほかのどの形と比べても 2 倍以上多く使われていれば、その形で印字する。
ER 図の `"CUSTOMER" ||--o{ "ORDER" : places` は、
`CUSTOMER ||--o{ ORDER : places` と印字する。
そこまで多く使われている形がないとき、または、
文書の例にその書き方が 1 つも出てこないときは、書かれたまま残す。

## 4. どの決まりも形を決めない所

上の 1 から 3 のどれからも形が出ないときは、どの形がいちばん読みやすいかが、
まだ決まっていない。
そのときは、作業をしている人の判断だけで、公開済みの版の出力を変えない。
形は、AGENTS.md の 4 にある決め方で決め、ここの決まりに書き足してから印字する。

## 対象にする mermaid.js の版

確かめは固定した mermaid.js だけで行うが、
整形した文章はほかの版の mermaid.js でも描かれる。
対象にする版は、固定した版が公開される前の 18 か月の間に公開された版のうち、
メジャーバージョンごとの、いちばん小さいマイナーバージョンと、
いちばん大きいマイナーバージョンである。
その間に足された図種については、
その図種を持つ最初のマイナーバージョンも対象にする。
どれも、そのマイナーバージョンの最新のパッチを使う。
版の一覧は、
[対象にする mermaid.js の版](./compatibility.ja.md#対象にする-mermaidjs-の版)
にある。

そのため、形は、次のどちらかのときも、書かれたまま残す。
1 つは、書かれた形を受け付ける対象の版の中に、
印字する形を受け付けない版があるときである。
もう 1 つは、対象の版の中に、印字する形を、
書かれた形とは違う図に描く版があるときである。
次の 3 つは、その例である。

- ヘッダーの名前（`block-beta` と `block`）は、対象の版の間で受け付けが違う。
- `@` を含む flowchart のラベルの `[` の後の空白（`A[ user@example.com ]`）は、
  それがないと、対象の版の一部がラベルを拒否する。
- subgraph のある flowchart のヘッダーの向き（`TB` と `TD`）は、
  対象の版の一部が違う描き方をする。

これに当たる場合のうち、固定している版だけでは要らないものは、どれも、
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
の表に 1 行ずつあり、その行が、どの版のために残すのかを、版の名前で書いている。
固定している版そのものが拒否するか、違う図に描く形は、
ほかの版が替わっても残すので、表に行を持たない。
版の名前を書くのは、この表だけである。
それぞれの図種の文書は、理由を書いて、表の行を指す。
固定する版を上げて、行が挙げた版が 1 つも対象でなくなったら、その規則を外し、
上の決まりが与える形で印字する。

どの版が形を足したか、変えたかは、mermaid.js の CHANGELOG.md か、
文法の履歴で分かる。

## 確かめ方と、Db を変える整形

整形が描くものを変えないことは、整形が Db を変えないことで確かめる。
Db は、mermaid.js が文章から読み取った内容である。
Db を変えても描くものを変えない整形は、例外とする。
例外の種類には、それぞれ、次の 3 つがある。
1 つめは、その種類を定義する節である。
2 つめは、描くものが変わらない理由を示す、
固定した mermaid.js のコードへのリンクである。
3 つめは、整形の前と後の文章をそれぞれ描いた結果である。
テストは、その種類の違いを元に戻してから、Db を比べる。
元に戻す関数は種類ごとに 1 つあり、
`packages/prettier-plugin-mmd/tests/db-comparison.ts` が呼ぶ。
固定した mermaid.js を更新するときは、例外ごとに、描いて確かめ直す。
種類は、次のとおりである。

- eventmodeling のブロックの本体の、限られた ASCII の空白の余白の変更。
  [Data blocks](./eventmodeling.ja.md#data-blocks) が定める。
- 対象になる state の note の段落の、余白の変更。
  [ノート](./state.ja.md#ノート) が定める。
- スタイルの最初の `:` と `,` のまわりの空白、
  スタイルの語の間の空白とタブの連なり（空白 1 つになる）、
  スタイルの末尾の空白。
  [同じに描かれるスタイル](./compatibility.ja.md#同じに描かれるスタイル)
  が定める。
