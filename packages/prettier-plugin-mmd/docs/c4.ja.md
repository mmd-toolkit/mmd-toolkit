# C4 の整形規則

英語版: [c4.md](./c4.md)

prettier-plugin-mmd による 5 種類の C4 図の整形です。
[C4 の構文](../../spec/docs/diagrams/c4.md)と
[木](../../spec/docs/ast/c4.md)に従います。
どの規則も mermaid.js の読み方を保ち、
同じ意味の書き方から 1 つを選ぶ場合は理由を示します。

以下では次の言葉を使います。

- **境界**は `System_Boundary(b, "B") { ... }` のように、
  波括弧の中に子を持つ呼び出しです。
  通常の呼び出しは `Person(a, "A")` などです。
- **空の説明ブロック**は `accDescr {}` など、
  空白とコメントと directive だけで説明の文字を持たないブロックです。
  文の区切りにはなりません。
  ヘッダーと必須の改行の間や、
  境界の呼び出しと開始の `{` の間にも置けます。
- **引数**は呼び出しの括弧の中の 1 項目です。
  **引用符なし**か引用符付きか名前付きの `$descr="D"` などで、
  文字のないものもあります。
  文字がなくても位置が mermaid.js の描画に影響することがあります。
- **directive** は `%%{ ... }%%` で、
  mermaid.js が図を読む前に取り除きます。
  **単独のコメント**はそれだけの行にあり、
  **末尾コメント**は同じ行の他の文字の後にあります。
  **図のコメント**は `Person(a, "A") %% note` のように、
  C4 の読み取りが扱うものです。
  U+2028 と U+2029 を越えて LF まで続き、
  後の空白だけの行が次の文の受理を左右することがあります。
- **行**は LF で終わり、
  CRLF と単独の CR は LF にそろえられます。
  共有の**セミコロンの行規則**ではコメントと directive の外の、
  U+2028 と U+2029 も境目です。
  `style` か `classDef` とコロンと後続のハッシュがこの順で現れると、
  規則が最後のセミコロンを除くことがあります。
  [共有の規則](../../spec/docs/common.md#style-and-classdef-lines)を
  参照してください。
  **保持する部分**はその読み方を保つために整形しない文字で、
  その行の最後のセミコロンまでです。
- **外側の空白**は値とコメントと directive の外にある空白で、
  `Person` の前の字下げや完了した呼び出しの後の空白などです。
  **ASCII の空白**は U+0020 です。

各節に固定の整形 fixture の入力と出力を示します。
見えない文字と行末の空白はエスケープで示し、
テストか fixture を引用します。
その文字列の `\n` は LF、
`\r` は CR、
`\t` はタブ、
`\u2028` と `\u2029` は Unicode の区切り文字です。
図にバックスラッシュが書かれる意味ではありません。
[文書と fixture](./development.ja.md#文書と-fixture)を参照してください。

## 規則

### ヘッダー

図の始まりを見つけやすくするため、
ヘッダーを先頭列に置きます。
`C4Context`、
`C4Container`、
`C4Component`、
`C4Dynamic`、
`C4Deployment` の種類は書かれたままです。
ヘッダーの後の改行は空の説明ブロックの後に残し、
末尾コメントと後続の空行や空白だけの行も保ちます。
その行を変えると mermaid.js が受理するかどうかが変わるためです。

### 字下げ

入れ子が分かるように、
文はヘッダーより 1 段深く置き、
境界の中ではさらに 1 段深く置きます。
閉じ波括弧は呼び出しにそろえます。
1 段は `tabWidth` と `useTabs` に従い、
既定では空白 2 つです。
単独のコメントと directive は周囲の文にそろえ、
セミコロンがある行でも同じ字下げにします。
値の続きの行は書かれた列を保ちます。
その空白が値の一部になることがあるためです。

### 境界の本体

requirement 図と同じように入れ子を見やすくするため、
`{` は呼び出しと空の説明ブロックの後に空白 1 つで続けます。
子は次の行から置き、
`}` は独立した行で呼び出しにそろえます。
セミコロンのある行の隣に `{` が書かれていても同じ形にします。
呼び出しと `{` の間に Unicode の区切り文字や、
コメントや directive がある場合は、
mermaid.js の読み方が変わるのを防ぐため改行を保ちます。
セミコロンや空の説明ブロックがある場合は、
後述の規則に従って `}` が直前の子と同じ行に残ることがあります。

### 空行

文のまとまりの間に空きすぎない間隔を置くため、
通常の連続する空行は 1 行にし、
図や境界の本体の端の空行は除きます。
単独のコメントや directive の前でも同じです。
受理されるかどうかが変わるのを防ぐため、
図のコメントの後の空行と空白だけの行は末尾まで保ちます。
値の中の空行はその内容として残します。
空白だけの説明ブロックの内側は、囲む本文がないので `{}` と印字します。

### コメント

文の間の位置を分かりやすくするため、
単独のコメントは次の文にそろえ、
ファイル末尾では最後の文にそろえます。
ヘッダーの前では先頭列に置きます。
末尾コメントは末尾に保ち、
間に空白があれば 1 つにし、
空白がなければ追加しません。
図のコメントの後の行とセミコロンのある行の保持する部分は、
この空白の規則より優先します。
タイトルやアクセシビリティの値の `%%` は値の文字として残し、
値の中のコメント行の境目も値を変えないために保ちます。

### 引数の空白

引数を変えずに一覧を読みやすくするため、
`(` の直後の空白を除き、
空でない引数の前のコンマには後ろに空白 1 つを置きます。
通常の引用符なしの引数の外側の空白も除きます。
閉じ引用符とコンマの間など、
それ自体が引数になる空白は保ちます。
`"` や `$` で始まる引用符なしの引数の前では、
ASCII の空白以外の空白を保ちます。
除くと引数の形が変わるためです。
隣接する引数と複数行の間隔と行内の directive の区切りを保ち、
`)` の前には空白を加えません。

### 改行文字

mermaid.js が LF として読むため、
CRLF と単独の CR は値の中も含めて `endOfLine` に従います。
値と間の文字とコメントと directive の U+2028 と U+2029 は保ちます。
LF に置き換えると値が変わったり、
拒否される隣接した呼び出しが受理されたりするためです。
コメントと directive の中では保持する行を分割しません。

既定の設定では入力 `"C4Context\rPerson(a,\"A\")\r"` を、
`"C4Context\n  Person(a, \"A\")\n"` と出力します。
入力 `"C4Context\nPerson(a, \"x;y\") %% c\u2028 x\n"` は、
`"C4Context\n  Person(a, \"x;y\") %% c\u2028 x\n"` と出力します。
`\u2029` も同じです。
`%%{init:\u2028 {}}%%` の directive も全体を保ちます。
テストはヘッダーと開始波括弧のコメント、
EOF で終わるコメントとコメントの外の区切り文字も示します。

### 空白文字

整形の空白だけを変えるため、
外側の通常のタブと NBSP と BOM と VT と FF と U+3000 は、
設定された空白にそろえます。
値とキーの内部の文字は保ちます。
`"` や `$` を引用符なしの引数の一部にする前置きの空白は保ち、
意味を変えない引用符なしの値の外側の空白は除きます。
U+0085 は値の文字として残し、
ファイル先頭の BOM は共有の Prettier の扱いに従います。

入力 `"C4Context\n\tPerson(a,\"A\")\n"` は、
`"C4Context\n  Person(a, \"A\")\n"` と出力します。
`Person(a,\t"A", "D")` は、
引用符なしの引数 `"A"` の前のタブを保ちます。
引用したテストは他の空白文字とキーや値の内部、
意味を変えない引用符なしの値の外側の空白と U+0085、
ファイル先頭の BOM も示します。

## 拒否される入力

共有の失敗処理は構文エラーを報告して元の文字を整形せず、
拒否される Markdown フェンスも整形しません。
ヘッダーや呼び出しの大文字と小文字、
ヘッダーと同じ行の呼び出しとキーワードの後の空白、
空の呼び出しや名前付きの値と区切りの不足、
通常のセミコロンと未対応のデータや direction 文、
空の本体と空の説明ブロックだけの本体を直しません。
たとえば `C4Context\nPerson()` は構文エラーのままで、
元の文字が残ります。
`comment-takes-line-break` の既知の差異に該当する入力も、
コメントを移動して mermaid.js の拒否を変えることはしません。
