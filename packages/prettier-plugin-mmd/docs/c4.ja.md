# C4 の整形規則

英語版: [c4.md](./c4.md)

prettier-plugin-mmd による 5 種類の C4 図の整形です。
[C4 の構文](../../spec/docs/diagrams/c4.ja.md)と
[木](../../spec/docs/ast/c4.ja.md)に従います。
どの規則も mermaid.js の読み方を保ち、
同じ意味の書き方から 1 つを選ぶ場合は理由を示します。

以下では次の言葉を使います。

- **境界**は `System_Boundary(b, "B") { ... }` のように、
  波括弧の中に子を持つ呼び出しです。
  通常の呼び出しは `Person(a, "A")` などです。
- **空の説明ブロック**は `accDescr {}` など、
  空白とコメントとディレクティブだけで説明の文字を持たないブロックです。
  文の区切りにはなりません。
  ヘッダーと必須の改行の間や、境界の呼び出しと開始の `{` の間にも置けます。
- **引数**は呼び出しの括弧の中の 1 項目です。
  **引用符なし**か引用符付きか名前付きの `$descr = "D"` などで、
  文字のないものもあります。
  文字がなくても位置が mermaid.js の描画に影響することがあります。
- **ディレクティブ** は `%%{ ... }%%` で、
  mermaid.js が図を読む前に取り除きます。
  **単独のコメント**はそれだけの行にあり、
  **末尾コメント**は同じ行の他の文字の後にあります。
  **図のコメント**は `Person(a, "A") %% note` のように、
  C4 の読み取りが扱うものです。
  U+2028 と U+2029 を越えて LF まで続き、
  後の空白だけの行が次の文の受理を左右することがあります。
- **行**は LF で終わり、CRLF と単独の CR は LF にそろえられます。
  共有の**セミコロンの行規則**ではコメントとディレクティブの外の、
  U+2028 と U+2029 も境目です。
  `style` か `classDef` とコロンと後続のハッシュがこの順で現れると、
  規則が最後のセミコロンを除くことがあります。
  [共有の規則](../../spec/docs/common.ja.md#style-行と-classdef-行)
  を参照してください。
  **保持する部分**は、その読み方を保つために、
  隙間と余白の空白の有無を保つ範囲です。
  [行規則とセミコロン](#行規則とセミコロン)を参照してください。
- **外側の空白**は値とコメントとディレクティブの外にある空白で、
  `Person` の前の字下げや完了した呼び出しの後の空白などです。
  **ASCII の空白**は U+0020 です。

各節に固定の整形 fixture の入力と出力を示します。
見えない文字と行末の空白はエスケープで示し、テストか fixture を引用します。
その文字列の `\n` は LF、`\r` は CR、`\t` はタブ、
`\u2028` と `\u2029` は Unicode の区切り文字です。
図にバックスラッシュが書かれる意味ではありません。
[文書と fixture](./development.ja.md#文書と-fixture)を参照してください。

## 規則

### ヘッダー

図の始まりを見つけやすくするため、ヘッダーを先頭列に置きます。
`C4Context`、`C4Container`、`C4Component`、`C4Dynamic`、
`C4Deployment` の種類は書かれたままです。
5 つの語は Db で別の種類を選ぶもので、別名ではないためです。
ヘッダーの後の改行は空の説明ブロックの後に残し、
末尾コメントと後続の空行や空白だけの行も保ちます。
その行を変えると mermaid.js が受理するかどうかが変わるためです。
ヘッダーの行に残る空の説明ブロックは、空白 1 つの後に置きます。

### 字下げ

[規則 1](./printed-form.ja.md#1-記号の横の空白)により、
文はヘッダーより 1 段深く置きます。
Prettier がブロックの中の行をそう印字するためです。
[規則 1](./printed-form.ja.md#1-記号の横の空白)により、境界の中の文は、
それを開く呼び出しの行より 1 段深く置き、閉じ波括弧は呼び出しにそろえます。
Prettier がブロックの中の行をそう印字するためです。
字下げで入れ子を示します。
1 段は `tabWidth` と `useTabs` に従い、既定では空白 2 つです。
単独のコメントとディレクティブは周囲の文にそろえ、
セミコロンがある行でも同じ字下げにします。
[規則 1](./printed-form.ja.md#1-記号の横の空白)により、
ブロックの中のそのようなコメントやディレクティブの行は、
ブロックを開く行より 1 段深く置きます。
Prettier がブロックの中の行をそう印字するためです。
値の続きの行は書かれた列を保ちます。
その空白が値の一部になることがあるためです。

### 境界の本体

境界の呼び出しが複数行に続く場合、見出しが完結する行を呼び出しにそろえます。
[規則 1](./printed-form.ja.md#1-記号の横の空白)により、
子はさらに 1 段深く置きます。
Prettier がブロックの中の行をそう印字するためです。
開始括弧を最後の呼び出し行にまとめる場合も同じです。
その行をまたぐ値は原文を保ちます。

`{` は呼び出しと空の説明ブロックの後に空白 1 つで続けます。
[規則 1](./printed-form.ja.md#1-記号の横の空白)がブロックを開く `{`
にそう与えるからです（Prettier は `class A{}` を `class A {}` と印字します）。
子は次の行から置き、`}` は独立した行で呼び出しにそろえます。
[規則 1](./printed-form.ja.md#1-記号の横の空白)により、
閉じる `}` は境界を開く呼び出しの行と同じ段に置きます。
Prettier がブロックの中の行と閉じる行をその深さに印字するためです。
セミコロンのある行の隣に `{` が書かれていても同じ形にします。
`System_Boundary(b, "x;")` の後の U+2028 か U+2029 と空白も、
空白 1 つにつなぎます。
それ以外で、呼び出しと `{` の間に Unicode の区切り文字や、
コメントやディレクティブがある場合は、
mermaid.js の読み方が変わるのを防ぐため改行を保ちます。
独立した `{` は呼び出しにそろえます。
値の内部にディレクティブがあっても、通常の波括弧の間隔は同じ行にまとめます。
セミコロンや空の説明ブロックがある場合は、
後述の規則に従って `}` が直前の子と同じ行に残ることがあります。

### 文ごとに改行

空の説明ブロック以外の文は、1 行に 1 つ置きます。
[flowchart](./flowchart.ja.md#1-行に-1-文) も、各文をそれぞれの行に印字します。
これは[規則 4](./printed-form.ja.md#4-どの決まりも形を決めない所)で決めた形で、
ここでは、
[規則 2](./printed-form.ja.md#2-prettier-にない種類の隙間)がこの形を与えます。
呼び出し、関係、更新、重複した別名の順序を保ちます。
宣言と更新は順序に依存するためです。
余分な引数の順序も保ちます。
1 行に書かれた 2 つの呼び出しは拒否され、直しません。
行を分けると mermaid.js の読み方が変わる箇所では、
空ブロックとセミコロンと行内のディレクティブの隣の文を同じ行に保ちます。
同じ行に残る 2 つの文の間に空白があるときは、空白 1 つです。

### 空行

通常の連続する空行は 1 行にし、図や境界の本体の端の空行は除きます。
単独のコメントやディレクティブの前でも同じです。
Prettier は JavaScript、CSS、YAML、Markdown でも、
文の間の通常の空行を最大 1 行にし、ブロックやテキストの端には残しません。
図や境界の本体の通常の空行にも、
[規則 1](./printed-form.ja.md#1-記号の横の空白)がこの形を与えます。
受理されるかどうかが変わるのを防ぐため、呼び出し（`Person`、`System`、
`Container`、`Component` などの要素の呼び出し、
`Rel` と `BiRel` などの関係の呼び出し、`UpdateElementStyle`、`UpdateRelStyle`、
`UpdateLayoutConfig`）の行、見出しの行、境界を開く行、境界を閉じる `}` の行、
または `accDescr {` ブロックの `}` の行を終えるコメントの後の、
空行と空白だけの行は、ファイルの末尾まで保ちます。
単独のコメントの後と、`title`、`accTitle:`、`accDescr:`、
`accDescription` の行を終えるコメントの後では、空行の連なりは 1 行になり、
ファイルの末尾には残りません。
値の中の空行はその内容として残します。
空白だけの説明ブロックの内側は、囲む本文がないので `{}` と印字します。

### コメント

単独のコメントは次の文にそろえ、ファイル末尾では最後の文にそろえます。
ヘッダーの前では先頭列に置き、文の間の位置を分かりやすくします。

### 引数の空白

Prettier がコンマに印字する形で、引数を変えずに、`(` の直後の空白を除き、
空でない引数の前のコンマには後ろに空白 1 つを置きます。
通常の引用符なしの引数の外側の空白も除きます。
閉じ引用符とコンマの間など、それ自体が引数になる空白は保ちます。
`Person("a"   ,"A")` の `"a"` の後の空白を保つのは、
対象にする版の mermaid.js のすべてが、
`Person("a", "A")` を違う図として描くためです（詳しくは
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
を参照）。
`"` や `$` で始まる引用符なしの引数の前では、ASCII の空白以外の空白を保ちます。
除くと引数の形が変わるためです。
`Person(a,\t"A", "D")` のタブを保つのは、対象にする版の mermaid.js のすべてが、
この形のラベルを引用符付きの `"A"` として描き、
`Person(a, "A", "D")` のラベルを引用符のない `A` として描くためです（詳しくは
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
を参照）。
`Person(a,\u00a0"A", "D")` の U+00A0 を保つのは、
対象にする版の mermaid.js のすべてが、
この形のラベルを引用符付きの `"A"` として描き、
`Person(a, "A", "D")` のラベルを引用符のない `A` として描くためです（詳しくは
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
を参照）。
隣接する引数と複数行の間隔と行内のディレクティブの区切りを保ちます。
コメントやディレクティブがある呼び出しでも、ほかの通常の余白は整えます。
`)` の前には空白を加えません。
最後の文字列の後に空白を加えると、閉じ括弧を飲み込む引用符なしの引数が始まり、
入力が拒否されることがあるためです。
隣接する引数の間にコンマは加えません。
引用符付きや名前付きの値の後の空白だけの引用符なしの引数は、
余白ではなく引数なので、書かれたまま残します。

### Quotes

要素や境界の別名と、関係や `UpdateRelStyle` の両端は引用符なしで、ラベル、技術、
型、要素の説明は引用符付きで印字します。
mermaid.js の文書の例がそのように書いているためです。
（[テキストの引用符](./compatibility.ja.md#テキストの引用符)）。
mermaid.js は文字列と引用符なしの引数を同じ引数として読むため、
`Person("a", "A")` と `Person(a, "A")` の Db は同じです。

引用符付きの別名は、ASCII の英字、数字、`_`、`-`、`.` と、
それらの間の空白からなり、直後に `,` が続く場合に引用符なしで印字します。
`Person("a", "A")` は `Person(a, "A")` と印字します。
引用符なしの引数は次の `,` まで続くため、引用符付きの別名の後に空白、タブ、
改行、別の文字列があると、それが別名の一部や別の引数になります。
呼び出しの最後の引数が引用符なしの場合は、`)` もその文字に含まれます。
そのため、`Person("a" , "A")`、`Person("d" "D")`、`Person("f")` は、
書かれたままにします。
`,`、`)`、`$`、`%`、`#`、`'`、ASCII 以外の文字、端の空白を含む別名と、
空文字列は引用符付きのままにします。
`)` を含む別名は、
[規則 3](./printed-form.ja.md#3-綴り)の直しにより引用符を保ちます。
引用符がないと、`Person(a), "A")` は `a` の後で終わる呼び出しに見えるからです。

### 名前付き属性

名前付き属性は `$key = "value"` とします。
Prettier が `=` を印字するときと同じく、同じ行の通常の間隔では、
`=` の両側に ASCII の空白を 1 つずつ置きます。
キーの内部の空白と引用符の中身は保ちます。
direction の文字を呼び出しの先頭行に移さないため、
`$` の後と `=` の前にある改行は空行も含めて保ちます。
境界の見出しが完結する行を除き、
継続行のトークンは設定した字下げ幅で呼び出しより 1 段深くそろえ、
独立した行のディレクティブも同じ深さにそろえます。
キーと引用した値の中の行は桁位置を保ちます。
名前付き属性のキーの中の行は、
字下げも mermaid.js が Db に持つ属性名の一部なので、書かれた列を保ちます。
字下げを変えると、別の属性名になります。
`=` の隣のコメントとディレクティブとセミコロンのある文字も保ちます。

### title と accDescription

[規則 1](./printed-form.ja.md#1-記号の横の空白)は、
`title` と `accDescription` のキーワードとテキストの間に、
区切り 1 文字として ASCII の空白 1 つを与えます。
Prettier が `return  x` を `return x;` と印字するためです。
テキストの先頭と末尾の空白とタブは除きます。
Db はそれらを持ちますが、mermaid.js はそれらがなくても同じテキストを描きます。
（[同じに描かれるキーワードの後のテキスト](./compatibility.ja.md#同じに描かれるキーワードの後のテキスト)）。
空白とタブだけのテキストは、書かれたままにします。
`title` の後に空白 3 つと改行がある形は、空白 3 つを保ちます。
対象にする版の mermaid.js はすべて、
`title` の後に改行だけがある形を違って描くためです（詳しくは
[対象にする版の mermaid.js のために残す形](./compatibility.ja.md#対象にする版の-mermaidjs-のために残す形)
を参照）。
テキストの中の空白とタブの連なりは、空白 1 つで印字します。
（[同じに描かれるテキスト中の空白の連なり](./compatibility.ja.md#同じに描かれるテキスト中の空白の連なり)）。
その区切り以降のほかの文字は、パーセントの文字も保ちます。
次の行の字下げは先頭の空白なので除きます。
`title` が 1 つ以上のディレクティブとその後の空白とタブで終わる場合は、
ディレクティブを最後にして印字します。
`title T  %%{x}%%  ` は `title T %%{x}%%` と印字し、
`title T  %%{x}%%  %%{y}%%  ` は `title T %%{x}%% %%{y}%%` と印字します。
`accDescription` も同じです。
（[同じに描かれるキーワードの後のテキスト](./compatibility.ja.md#同じに描かれるキーワードの後のテキスト)）。
ただし、行のディレクティブのどれかに改行、`;`、U+2028、U+2029 があるときは、
その行の印字は、
表の C4 diagram の `title` と `accDescription` の行のとおりです。
（[改行かセミコロンを含むディレクティブ](./compatibility.ja.md#改行かセミコロンを含むディレクティブ)）。

[fixture: title-and-accdescription/title-trailing-directive-blanks-dropped]
[fixture: title-and-accdescription/title-two-directives-trailing-blanks-dropped]
[fixture: title-and-accdescription/description-trailing-directive-blanks-dropped]
[fixture: title-and-accdescription/description-two-directives-trailing-blanks-dropped]

区切りが改行なら同じ行に続けますが、
direction の文字が先頭行に出る場合は改行を保ちます。
Unicode の区切り文字とコメントとディレクティブとセミコロンが、

通常のコロン形式は `accTitle: value` か `accDescr: value` とします。

次の行の値は同じ行に続けますが、
direction の文字とコメントとディレクティブとセミコロンが、
元の改行を必要とする場合は保ちます。

コロン形式では、コメントとディレクティブの改行と接触を保ちます。

### 行規則とセミコロン

セミコロンは C4 の文の区切りではないため、すべて保ちます。
C4 に style 文がなくても共有の行規則は文字の中に働き、
前述のようにセミコロンを取り除くことがあります。
保つ `;` を含む区間は、行の規則が無視する `;` が整形で変わる所を除き、
ほかの場所と同じように整形します。
この規則は、[セミコロン](./flowchart.ja.md#セミコロン)のとおり、
`style` か `classDef` の後の最初の `:` から、
最後の保つ `;` の前の最後の `#` までに空白がない並びを読みます。
その範囲の隙間と余白は空白の有無を保ち、空白の連続は空白 1 つにします。
範囲の外は、この図種の通常の規則に従います。
字下げは printer が決め、外側の末尾空白を除きます。
[規則 1](./printed-form.ja.md#1-記号の横の空白)により、セミコロンのある文も、
周りの文と同じ段に置きます。
Prettier がブロックの中の行をそう印字するためです。
行の末尾で保護する文字の範囲の外にある空白とタブは、
[規則 1](./printed-form.ja.md#1-記号の横の空白)により除きます。
Unicode の区切り文字はコメントとディレクティブの外側でだけ境目とし、
その中ではコメントとディレクティブを分割しません。

### 末尾の改行

共有のファイルの規則にそろえるため、
通常の受理される図の末尾には設定された改行を置きます。
通常の受理される図の末尾の改行 1 つは、JavaScript、CSS、YAML、
Markdown に Prettier が印字する形と同じで、
[規則 1](./printed-form.ja.md#1-記号の横の空白)が形を与えます。
最後のコメントの後に改行がない場合も、改行を補います。
最後にあるコメントは、同じ行でテキストの後に続くもの（空白、タブ、U+2028、
U+2029 を含む）を書かれたまま残し、改行 1 つでテキストを終えます。
ただし、呼び出し、関係、境界を閉じる `}` の行で、
コメントの前にディレクティブがあるときは、空白とタブを落とし、
ほかの空白文字は残します。
テキストが改行なしで終わっているときは、印字が改行を足します。
コメントが呼び出しの行、境界を開く行、境界を閉じる `}` の行、
または `accDescr {` ブロックの `}` の行の末尾にあるときは、
その後ろの空行も書かれたまま残します。
コメントだけの行にあるときと、`title`、`accTitle:`、`accDescr:`、
`accDescription` の行を終えるときは、空行を落とします。
Prettier は JavaScript、CSS、YAML の行末でも、空白とタブを取り除きます。
呼び出し、関係、境界を閉じる行で、
最後のコメントの前にディレクティブがある場合も、行末の空白とタブは、
[規則 1](./printed-form.ja.md#1-記号の横の空白)が取り除きます。
`title` か `accDescription` の行を終えるコメントは、
その後ろの空白とタブを落とし、ほかの空白文字は残します。
`accTitle:` と `accDescr:` の行を終えるコメントは、U+00A0、U+3000、U+2028、
U+2029 を含む仕様の空白文字をすべて落とし、U+0085、U+180E、U+200B は残します。
U+0085、U+180E、U+200B は仕様の空白文字ではなく、
`accTitle:` と `accDescr:` の値の文字として残ります。
これらを除くと、mermaid.js が読む値が変わるためです。
呼び出しのコメントの後で、改行が後ろになく、
前に空行もない最後の空白だけの行（U+2028 と U+2029 を含む行を除く）は落とし、
後ろに改行があるものと、空行の後のものは残します。
空行の後の行には、後ろに改行を足します（`Person(a, "A") %% c`、改行、空行、
空白 1 つは、コメント、空行、空白と、その後ろの改行を印字します）。
境界を閉じる `}` のコメントの後と、
`accDescr {` ブロックの `}` のコメントの後も同じです。
呼び出しのコメントの後で、
後ろに改行がなく前に空行もない最後の空白とタブだけの行は、
U+2028 と U+2029 を含まなければ、末尾の空行に当たります。
その行を除き改行 1 つで終える形を、
[規則 1](./printed-form.ja.md#1-記号の横の空白)が与えます。
U+2028 か U+2029 を含む最後の行は、単独でも空白が添えてあっても、
呼び出しのコメントの後と、境界を閉じる `}` のコメントの後と、
`accDescr {` ブロックの `}` のコメントの後では残り、
後ろに改行がなければ足します（`Person(a, "A") %% c`、改行、U+2028 は、
コメントと、U+2028 の行と、改行を印字します）。
コメントだけの行の後と、`title`、`accTitle:`、`accDescr:`、
`accDescription` の行を終えるコメントの後では、空白だけの最後の行はどれも、
U+2028 か U+2029 を含む行も、落とします（`Person(a, "A")`、改行、`%% c`、改行、
U+2028 は、`Person(a, "A")` と `%% c` に、それぞれ改行を付けて印字します）。
コメントだけの行と、`title`、`accTitle:`、`accDescr:`、
`accDescription` の行を終えるコメントの後では、
最後の空白とタブだけの行も空行に当たります。
末尾に空行を残さず改行 1 つで終える形を、
[規則 1](./printed-form.ja.md#1-記号の横の空白)が与えます。
語の引数を持つ閉じていないディレクティブは、その語と後ろの空白だけを取り込み、
その後ろのテキストはディレクティブの行に乗ります。
詳しくは
[閉じていないディレクティブがつなぐ行](./compatibility.ja.md#閉じていないディレクティブがつなぐ行)
を参照してください。
`Person(a, "A")`、`%%{x`、`y`、`Person(c, "C")`、`Person(d, "D")` では、`a`、
`c`、`d` が残ります。
閉じていないディレクティブがテキストの終わりまで届くとき（`%%{init: {`
のように語の文字で始まらない引数を U+2028 や U+2029 が止めないときなど）は、
空白でない最後の文字までの残りを取ります。
ここでは U+2028、U+2029、U+0085、U+180E、U+200B を空白でない文字に数えます。
その文字の後ろの空白は、文の行でも落とします。
落とすのは U+0009 から U+000D（タブ、改行、垂直タブ、改ページ）、U+0020、
U+00A0、U+1680、U+2000 から U+200A、U+202F、U+205F、U+3000、U+FEFF と、
空行です。
改行 1 つでテキストを終えます。
何も足さないのは、テキストがその文字の直後で終わり、
その文字が U+2028 でも U+2029 でもないときだけです。
Markdown がフェンスとその外の字下げを決め、
中の C4 の文字には同じ整形規則を使います。

### 改行文字

### 空白文字

整形の空白だけを変えるため、
外側の通常のタブと NBSP と BOM と VT と FF と U+3000 は、
設定された空白にそろえます。
値とキーの内部の文字は保ちます。
ただし、ラベル、技術、型、説明の中の空白とタブの連なりは、
空白 1 つにして印字します（[引数の形](#引数の形)を参照）。
名前付き属性のキーの中の NBSP は、mermaid.js が Db に持つ属性名の一部なので、
残します。
ASCII の空白に置き換えると、属性名が変わります。
U+2028 か U+2029 を含むテキストは、連なりも含めて書かれたまま残します。
これらはテキストの文字で、mermaid.js はそれらで行を読むからです。
`"` や `$` を引用符なしの引数の一部にする前置きの空白は保ち、
意味を変えない引用符なしの値の外側の空白は除きます。
U+0085 は値の文字として残し、
ファイル先頭の BOM は共有の Prettier の扱いに従います。
U+0085 は仕様の空白文字ではないため、
引用符なしの引数でも値の文字として残します。
除くと、mermaid.js が読むラベルが変わります。

## 拒否される入力

共有の失敗処理は構文エラーを報告して元の文字を整形せず、
拒否される Markdown フェンスも整形しません。
拒否される入力には保つべき Db がないので、printer は読み方を主張せず、
直しません。
直したり実行時に確かめたりすると、足りない字句の規則が隠れ、規則になりません。
ヘッダーや呼び出しの大文字と小文字、
ヘッダーと同じ行の呼び出しとキーワードの後の空白、
空の呼び出しや名前付きの値と区切りの不足、
通常のセミコロンと未対応のデータや direction 文、
空の本体と空の説明ブロックだけの本体を直しません。
たとえば `C4Context\nPerson()` は構文エラーのままで、元の文字が残ります。
`comment-takes-line-break` の既知の差異に該当する入力も、
コメントを移動して mermaid.js の拒否を変えることはしません。
