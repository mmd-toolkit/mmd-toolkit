## トークン

| 種類         | 要素                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| `Keyword`    | 各見出し、呼び出しのキーワード、`title`、`accDescription`、`accTitle`、`accDescr`  |
| `Punctuator` | `(`、`(,`、`)`、`,`、`,,`、`{`、`}`、`:`、`$`、`=`                                 |
| `RawText`    | 各裸の引数、名前付きのキー、タイトル値、コロンのアクセシビリティ値、説明ブロック値 |
| `String`     | 両端の引用符を含む、引用された引数または名前付きの値全体                           |

表の各要素は、共通の trivia で切られる前には 1 つのトークンを作ります。
空の引数を始める `(,` は、記号間の ASCII 空白も同じトークンに含みます。
`,,` も 1 つのトークンです。
末尾の単独のコンマは自身のトークンを持ち、引数を増やしません。
空の引用された引数にも `String` トークンがあります。
数のようなテキストを含め、`Identifier` や `Numeric` の要素は使いません。

字句解析器は、タイトルの行値の一致をキーワードと値に分け、
最初の空白区切りを両方のトークンの外に置きます。
値は、その後の先頭と末尾の空白を、空白だけの値も含めてすべて保ちます。
裸の引数、名前付きのキー、コロン値、ブロック値は外側の空白を除きます。
空白だけの裸の引数とキーには、テキストのトークンがありません。
文字列は内部の空白をすべて保ちます。
内部の行終端子は、トークンの中で書かれた綴りを保ちます。

名前付きの値の `=` と開きの引用符は別の単位です。
`=` は `Punctuator` の要素で、開きの引用符は `String` の要素を始めます。
両者の間のディレクティブや選ばれたセミコロンは、どちらの要素も切りません。

先頭の文脈の空白と `newline` 単位は、トークンを作りません。
空の説明ブロックは、文でも両方の `beforeBody` の並びでも、
キーワードと両方の波括弧のトークンを持ちます。
図のコメントは `Root.comments` に記録し、行終端子の前で終えます。

ディレクティブ、共通のコメント領域、
選ばれた無視するセミコロンは、
[共通規則](../tokens.ja.md#ディレクティブが切るトークン) に従って、
テキストと文字列を切ります。
切られた `String` は `StringFragment` トークンになります。
キーワードや区切りの内部で切れると、入力を拒否します。
`Directive` と `IgnoredSemicolon` は共通の記録処理が作ります。
