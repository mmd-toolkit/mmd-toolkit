## Tokens

| Kind         | Items                                                                                              |
| ------------ | -------------------------------------------------------------------------------------------------- |
| `Keyword`    | Each header, call keyword, `title`, `accDescription`, `accTitle`, and `accDescr`                   |
| `Punctuator` | `(`, `(,`, `)`, `,`, `,,`, `{`, `}`, `:`, `$`, and `=`                                             |
| `RawText`    | Each bare argument, named key, title value, colon accessibility value, and description-block value |
| `String`     | A complete quoted argument or named value, including both quotes                                   |

Each listed item makes one token before common trivia cuts it. The opening
empty-entry form `(,` includes any ASCII spaces between its two marks in that
one token; `,,` is likewise one token. A lone trailing comma has its own token
and adds no argument. An empty quoted argument still has a `String` token. No
`Identifier` or `Numeric` items are used, including for number-like text.

The lexer splits a title line-value match into its keyword and its value,
leaving its first whitespace separator outside both tokens. The value keeps all
additional leading and trailing whitespace, including a whitespace-only value.
Bare arguments, named keys, colon values, and block values leave exterior
whitespace outside their tokens; a whitespace-only bare argument or key has no
text token. Strings keep all interior whitespace. Internal line terminators keep
their original spelling in tokens. [fixture: c4/db-title-whitespace] [fixture:

The `=` and opening quote of a named value are separate units: `=` is a
`Punctuator` item, and the opening quote starts the `String` item. A directive
or selected semicolon between them cuts neither item. [fixture:
